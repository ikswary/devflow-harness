# 목적 시험 지시문 틀

목적 시험(`tests/purpose/README.md`)에서 에이전트에게 주는 지시문이다. 작성자와 판정자에게는 하네스 프롬프트 틀
(`references/formats/prompt.md`)을 그대로 쓰고 아래 줄만 「이번 지시에만 있는 것」에 덧붙인다. 결과를 모르는 승인자에게는
마지막 절을 그대로 준다. `{…}`는 돌릴 때 채우는 자리 표시다.

승인자 절에는 대조할 판단 자리, 앞 회차의 결과, 고친 까닭을 넣지 않는다. 넣으면 시험이 무효다(원칙 문서 4절 "지시문에
사후 지식을 넣지 않는다"). `tests/py/test_purpose_setup.py`가 그 절의 낱말을 본다.

## 작성자에게 덧붙일 것

```
이번 지시에만 있는 것: 이 실행은 목적 시험 폴더 {시험 폴더} 안의 사본이다. {시험 폴더} 밖의 파일을 읽거나 쓰지 않는다.
원격 저장소·배포·외부 서비스에 닿는 명령(git push, git fetch, 배포·설치 명령, 원격 DB 접속)을 돌리지 않는다. 그런 명령이
필요하면 돌리지 않고 결과 파일의 「확인 안 된 것」에 적는다.
```

## 판정자에게 덧붙일 것

```
이번 지시에만 있는 것: 이 실행은 목적 시험 폴더 {시험 폴더} 안의 사본이다. {시험 폴더} 밖의 파일을 읽거나 쓰지 않는다.
원격 저장소·배포·외부 서비스에 닿는 명령(git push, git fetch, 배포·설치 명령, 원격 DB 접속)을 돌리지 않는다. 그런 명령이
있어야 답할 수 있는 기준은 판정불가로 둔다.
```

## 결과를 모르는 승인자 지시문

```
당신은 이 개발 작업을 맡긴 사람이다. 하네스가 승인을 받으려고 보낸 화면 하나를 받았다.

읽을 것: {화면 파일}. 화면이 펼쳐 보라고 가리키는 파일({펼침 경로})은 필요할 때만 연다. 그 밖의 파일은 읽지 않는다.
펼침을 열었으면 무엇을 알려고 열었고 거기서 찾았는지 적는다.

화면만 보고 실제로 답한다고 생각하고, 아래 아홉 절로 {결과 파일}에 쓴다. 절마다 화면의 어느 줄을 보고 그렇게 판단했는지 적는다.

## 1. 답
화면이 받는 꼴로 실제로 보낼 답 한 줄과, 고른 까닭.
## 2. 답하기 전에 확인할 것
답하기 전에 알아보거나 누구에게 물어야 할 것. 없으면 없다고 쓴다.
## 3. task가 무엇이고 왜 필요하며 무엇과 비교했는지
화면에서 알 수 있었던 것과 알 수 없었던 것.
## 4. 실행 전체에서 어디쯤인지, 벗어나고 있는지, 왜 길어졌는지
## 5. 이미 정한 것, 바꾸는 것, 새로 정하는 것의 구별
구별할 수 있었는지, 헷갈린 줄이 있었는지.
## 6. 하네스가 스스로 고치겠다고 한 것 가운데 내가 정하고 싶었던 것
## 7. 묻지 않아도 됐던 질문, 물었어야 했던 질문
## 8. 감당할 만했는지, 읽기 힘들게 만든 것
읽는 데 든 수고, 다시 읽어야 했던 곳, 뜻을 모른 낱말.
## 9. 이 꼴로 계속 받는다면
이 꼴의 화면을 계속 받으며 일할 수 있는지, 무엇이 바뀌어야 하는지.
```
