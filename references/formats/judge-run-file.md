실행 판정 파일 `judge-run.md`(5절의 실행 판정 몫)는 실행 판정자가 직접 쓴다.

- 첫 줄은 읽기 판정 파일과 같은 `판정자: {인스턴스 이름} {YYYY-MM-DD HH:MM:SS}`이다.
- `## 통과 못 한 기준` 절에는 기준선 밖 실패와 판정불가를 쓴다. 항목은 `- 기준 {n}`·`- 변이 {n}`으로 시작하고, 없으면 `- 없음`이다. `screen.py`가 이 절을 읽는다.
- 변이의 판정불가는 `- 변이 {n}: 판정불가 {꼬리표}: {이유}`다.
- 그 아래에 명령별 결과(통과/실패/판정불가, 수치)를 쓴다.
- 기준선에 있던 실패와 새 실패를 가른다. 새 실패는 상위 10건(나머지는 "외 N건"), 기준선에 있던 실패는 수를 쓴다.
- 변이 확인 결과는 항목별로 바꾼 줄, 실패한 테스트, 되돌린 뒤 `git diff` 일치 여부를 쓴다.
- 배포 뒤 확인이면 확인마다 시각·작업 폴더·명령·종료 코드·로그를 쓴다.
- `## 검사 입력과 독립 근거` 절에 검사마다 아래 이름을 빠짐없이 쓴다. 한 줄에 모아도 된다: `제품 commit/diff:`, `시험 소스:`, `설정:`, `lock/설치:`, `명령:`, `환경 초기화:`, `판정자:`, `시각:`, `종료 코드:`, `로그:`. DB는 URL 외에 초기화·seed·snapshot 식별과 그 실행 근거를 `환경 초기화:`에 쓴다.
- `## 남은 검사와 자원 대기` 절에 실행하지 않은 검사와 잠금 owner를 쓴다. 모두 끝났으면 `- 없음`이다. 공유 자원 사용 중은 실패·판정불가 항목으로 쓰지 않는다. 이 절에 항목이 남으면 승인·완료·재시도 보관이 거부된다.
- 앞 독립 결과의 재사용은 모든 검사 입력이 같고 독립 근거가 있는 항목만 허용한다. 최종 배포 후보 CI는 앞 task의 부분 검사 결과를 재사용하지 않는다.
- 승인된 신규 1.0.2 B 실험에서만 새 전체 CI 시작 전에 `## 재사용 가능성 관측`을 쓴다: `판정: 가능/불가/판정불가`, `고정 기록: {shadow manifest 경로·hash}`, `원 CI: {task·judge-run·로그·artifact}`, `후보쌍: {원 full SHA→현재 full SHA}`, `입력 동일성: {시험·명령·설정·lock/설치·artifact·환경/DB별 근거}`, `신선함: {외부 쓰기·변경 부재 근거}`, `관측 시각:`, `새 전체 CI 시작 시각:`. 누락은 관측 제외이며 기존 gate를 막지 않는다.
- `재사용 가능성 관측`의 결론과 무관하게 이번 판의 전체 CI를 새로 모두 실행한다. 관측 뒤 입력이 바뀌거나 CI가 먼저 시작됐으면 비교에서 제외하며, 가능 건수·원 CI 시간은 잠재 절감량일 뿐 실제 절약으로 세지 않는다.
- 이번 회차의 마지막 통합과 마무리 내보내기 후보에는 `## 최종 배포 후보 CI` 절에 `- 범위: 전체 검증`, `- 검증 commit: {후보 commit}`, `- 검증 artifact: {CI 실행·산출물 식별자}`를 쓴다. 마무리는 흐름 하나여도 생략하지 않는다. commit은 7~40자 16진수 Git SHA여야 하며 세 값이 없거나 범위·commit이 다르면 완료 전이가 거부된다.
- 배포 결과를 유지하면 `## 배포 대상 동일성` 절에 `검증 commit:`, `검증 artifact:`, `배포 commit:`, `배포 artifact:`를 쓰고 commit끼리, artifact끼리 같아야 한다. 이 검증 쌍은 현재 실행에서 최근 완료된 1.0.1 마무리의 `최종 배포 후보 CI` commit·artifact와도 각각 같아야 하며, 머리 파일의 `deployed_commit`도 배포 commit과 같아야 완료된다.
