## 4. 결과 파일 `result.md` (작성자)

절의 제목과 순서를 지킨다. 스크립트가 제목으로 읽는다.

```
# {task id} {제목} 결과

## 승인 화면
### 정해 주실 것
- (항목마다: 무엇을 정하는지 한 문장 / 지금 상태와 이 결정이 왜 생겼는지 / 선택지마다 달라지는 것 / 추천과 이유.
   선택지별로 산출물에 들어갈 문장이 정해져 있으면 `선택지 (가)의 문장:` `선택지 (나)의 문장:`을 하위 줄로 적는다.
   실행할 명령은 항목 아래 `cmd` 울타리(백틱 셋 뒤에 cmd를 붙인 줄로 열고 백틱 셋으로 닫음)에 한 줄에 하나씩, 자리 표시 없이 그대로 적는다. 사용자가 돌릴 줄은 앞에
   `[사용자 실행]`, 유지 뒤에만 돌 줄은 `[유지 뒤]`. 승인 뒤 `exec.py`가 이 줄을 얼리고 이 줄만 돌린다)
### 하실 일·허용 요청
### 알릴 것
### 답하신 것의 반영
### 확인 안 된 것
### 건수만
칸이 비면 `- 없음`(설명을 붙이려면 `- 없음 (설명)`)이고, 항목은 맨 앞이 `- `인 줄 하나가 하나이며 하위 설명은 들여쓰고, 번호·표·문단으로 쓴 칸은 `screen.py`가 세지 못해 알림을 막는다. [RP-02]

## 결정 지도
(기획·요구사항·화면 설계·설계·원인 분석. 결정 목록, 결정 사이의 의존, 사용자 결정 표시. 본문보다 먼저 쓴다)

## 스스로 줄임
(줄였으면: 이유, 여기까지 닫은 범위, 넘긴 기준과 그것을 닫을 자식, "여기까지면 의존하는 쪽이 시작할 수 있다" 표시. 안 줄였으면 `없음`)

## 본문
(정본을 처음 쓰는 task는 정본 경로와 쓴 절의 목록. 그 밖에는 이 task의 산출물)

## 자식 목록
나눈 기준: (한두 줄. 무엇을 기준으로 나눴고 왜)

### 자식: {제목}
- kind: implementation
- flow: contact-form
- depends_on: (형제의 제목 또는 이미 있는 task id. 쉼표로)
- difficulty: 일반
- closes_ac: AC-07, AC-08
- partial_ac:
- option: (선택지 행만. 아래)
- 한 줄: (승인 화면에 올릴 한 줄)
#### 범위
#### 판정 기준
#### 건드릴 파일
- src/forms/example.tsx
#### 시그니처와 결정 번호
#### 정본의 절

## 규약 추가
(코드 task. 새로 만든 공용 이름·형식·오류 코드, 기각한 대안. 없으면 `없음`)

## 변이 확인 지시
코드 task는 인수 기준을 닫는 테스트마다 파일:줄, 어떻게 바꾸는지, 실패해야 하는 테스트, 효과 근거, 돌릴 명령을 적는다. [RP-03]

## 커밋 메시지
(코드 task. 저장소의 커밋 스타일. AI 표시 줄을 붙이지 않는다)

## 실행 기록
(작성자가 돌린 명령과 결과 요약)
```

- 자식이 없는 task는 `## 자식 목록` 절을 두지 않는다.
- 자식 행의 kind가 등록표 `needs_touch_files`(`references/registry/kinds.md`)이면 그 행에 「건드릴 파일」이 반드시 있어야 한다. 없으면 `spawn_children.py`가 머리 파일을 만들지 않는다.
- 같은 흐름의 코드 task는 자식 목록에 적은 순서대로 앞 task에 자동으로 의존한다.
- `option`: 승인에서 고를 선택지의 행(원인 분석의 수정안, 검증의 「묻는다」 지적, 설계의 배포 선택지)에 `{묶음}/{안}`으로 적는다(원인 분석은 `수정안/가`, 검증은 `V-01/가`). 행 하나가 여러 안에 걸치면 쉼표로(`배포/나, 배포/다`). 메인이 고른 안을 `spawn_children.py --option`으로 넘기면 고른 안이 든 행과 `option`이 없는 행만 생긴다. 사용자가 백로그로 남기라고 답한 안은 `--backlog-option`으로 넘겨 그 행을 `백로그`로 만든다. 제목이 `[백로그]`로 시작하는 행은 `백로그` 상태로 생긴다.
