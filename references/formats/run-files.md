## 6. 그 밖의 파일

`run.md`
```
---
kind: devflow-harness
status: 진행              # 진행 / 완료 / 중단
project: D:\workspace\myapp
base_branch: dev
round: 1                   # 회차. 새 실행 1, 다시 열 때마다 +1
integration_branch:        # 흐름이 둘 이상으로 정해지면 채운다
integration_dir:
harness_version: {devflow_lib.harness_version()의 값: `.claude-plugin/plugin.json`의 `version`}
start_task: T001
previous_run:              # 백로그·이전 결과를 이어받으면 경로
session_id:                # 지금 세션의 id. 메인이 시작·재개·다시 열기 때 덮어씀
---
## 요청 원문
## 다시 연 요청 ({날짜})   # 끝난 뒤 다시 열 때마다 하나. 요청 원문, 이어받는 task 경로
## 시작 때 원래 폴더의 git status
## 이번 실행의 값
| 값 | 이번 실행 |
## 발견 점검
(에이전트 8종이 보이는지)
## 남은 정리               # 실행의 끝 정리 단계를 사용자가 미룬 폴더·브랜치 목록. 없으면 절을 두지 않는다
```

`flows\{흐름}\flow.md`
```
---
flow: common
role: feature              # feature / fixes / integration / deploy. 없으면 이름으로 추정(fixes·fixes-r2, integration·integration-r2, deploy-1)
round: {run.md의 round}    # 이 흐름의 회차. 첫 코드 task 행을 만들 때나 그 task가 시작될 때 스크립트가 run.md round로 채운다. 없으면 1
branch: harness/example/common
dir: D:\workspace\myapp-example-common
base_commit:
depends_on_flows: []       # 이어 붙인 만드는 흐름(먼저 합쳐져야 함). 없으면 빈 목록
branched_from:             # 이어 붙이기면 {만드는 흐름}@{커밋}. 아니면 비움(통합 브랜치에서 갈라짐)
sync_pending: []           # 받아올 출처 {브랜치}@{커밋}. 받아온 뒤 비움
synced_to:                 # 마지막으로 받아온 출처 {브랜치}@{커밋}
status: 폴더 없음          # 폴더 없음 / 진행 / 검증 끝남 / 합쳐짐 / 폴더 지움(실행의 끝 정리 단계가 지운 뒤)
---
```

`main-run.md`: 줄마다 `- {시각} | {직접 실행/기계 대조/칸 옮김/준비된 선택지/정정} | {기준 n·변이 n 또는 칸} | {결과 한 줄} | 로그 {경로}`. 직접 실행의 결과에 "통과"가 있으면 `screen.py`가 같은 기준의 판정불가를 세지 않는다.

`exec.md`: 줄마다 `- {시각} | {명령 그대로} | 종료 코드 {n} | 로그 {경로} | 지점 {지점}:{n} | 폴더 {경로}`(`exec.py`가 씀. 병합 줄 뒤에는 `- {시각} | 브랜치 판정 | {지점}:{n} | {병합/앞감기/충돌/불일치} | …`). 백그라운드로 띄운 명령은 `| PID {pid}`를 붙이고, 거둔 뒤 `- {시각} | taskkill /PID {pid} /T /F | 종료 코드 {n}` 줄을 더한다(메인).

`journal.md`: 줄마다 `- {시각} | {일: 합치기/재개/한도 정지/값 변경/폴더 생성/메모} | {관련 task} | {한 줄}`.

`decisions.md`: 줄마다 `- {시각} | {결정} | 원문: "{…}" | 관련 task`. 바뀌면 옛 줄에 `→ 대체: {시각}`.

`recon.md`: 정찰 결과(정찰 방법 문서)에 더해 `## 기준선`(원래 실패하던 테스트 가운데 사용자가 확인한 것), `## 공유 자원과 잠금`(잠금·상태 명령, 스스로 잠금을 잡는 명령, 있으면 최종 배포 후보 전체 검증 기록 명령과 그 기록의 commit·artifact 식별), `## 합치기 관례`, `## 폴더 준비`(의존성 설치 명령, 설치가 lock 파일과 맞는지 보는 확인 명령(예: `npm ls --depth=0`, 없으면 없음), 준비할 비밀 파일과 방법, 시험 자료 준비), `## 재시도 기록`(계층마다 재시도 설정 위치와 재시도된 시험을 보는 명령·파일. 없으면 "볼 수단 없음" — 빌드·시험 방법 문서의 「흔들림과 재시도」), `## 문서를 읽는 검사`(문서를 읽는 검사 명령, 예: `check:static`이 `docs/deploy.md`를 읽음. 문서만 바꾸는 구현의 실행 판정이 관련 테스트로 쓴다. 없으면 `없음`), `## UI 규약`(디자인 토큰 파일(CSS 변수, `Theme.kt`, tailwind 설정 등), 컴포넌트 폴더, 스타일 가이드·문구 규칙 문서, 화면 코드 폴더, 화면 시험 도구(Playwright, Compose test 등)와 시험 표식 관례(`data-testid`·`testTag`). 덧대기식 스타일 파일 더미는 규약이 아니다. 화면 설계 task가 읽는다. 없으면 `없음(스타일 파일 n개)`).

프로젝트 설정(프로젝트마다 한 번 정하는 것): `{호출한 폴더}\_workspace\devflow-harness.project.md`에 의존성 설치 명령, 준비할 비밀 파일의 목록과 준비 방법, 시험 자료 준비(git 밖 파일 복사와 명령, 없으면 `없음`), 개발 기준 브랜치, 내보내기 방식(병합/PR), 줄 끝 고정(`적용함`/`안 함`)을 적는다. 운영 배포가 있는 프로젝트는 선택 항목으로 `운영 브랜치`(예: `main`), `운영 브랜치 옮기기`(지금 정의된 값은 `유지 뒤 앞감기`뿐), `운영 브랜치 push`(`예`/`아니오`)를 적는다. 없으면 운영 배포가 운영 브랜치를 건드리지 않는다. 있으면 다시 묻지 않는다.

측정 기록(프로젝트마다 실행이 쌓이는 것): `{호출한 폴더}\_workspace\measure.md`의 표. 한 행이 실행 하나(다시 연 실행은 다시 연 뒤의 구간 하나)다. 처음 만들 때는 아래 머리 두 줄만 둔다.
| 실행 | 이번 실행의 값(바꾼 것만) | task 수(종류별) | 승인 / 알림 | 승인 하나의 사람 판단 항목(중앙값 / 최대, 최대인 task) | 자식 행 수 최대 | `나눠서 다시` | 스스로 줄인 횟수(이유별) | 산출물을 바꾸는 답 / 고친 판을 쓰는 전용 task | 되물음 | 자체 검증 재시도 | 판정불가 | 자체 검증 통과 뒤 검증에서 잡힌 지적 | 알림 task의 숨은 예외 | 판정자가 칸을 옮긴 항목 | 수정 세대 최대 | 흐름을 합칠 때의 충돌 | 메인 컨텍스트 최대 | 비고 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
