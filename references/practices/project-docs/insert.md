# 프로젝트 산출물: 넣기

읽는 때: 메인과 마무리 작성자가 `docs_base_commit`이 있는 실행의 마무리를 다룰 때.

`project_docs.py {실행 폴더} {마무리 id} --insert {코드 폴더}`가 기준본, 프로젝트 쪽(코드 폴더. 그대로면 개발 기준 브랜치), 이번 실행 판을 `##` 절마다 견주어 합쳐 코드 폴더에 쓰고 그 task 폴더에 표 `docs-insert.md`를 쓴다. 코드 폴더를 정할 수 없으면 쓰지 않고 표만 낸다.

| 표의 말 | 뜻 | 마무리 리뷰 |
|---|---|---|
| 승인한 그대로 | 넣은 글의 원천이 사람이 승인한 판이다 | 파일 이름 |
| 승인 없이 알림으로(위임으로) 지나감 | 5.1절의 길로 지나갔다 | 파일 이름 |
| 대조하지 못함 | 물을 때의 사본이 없어 사람이 본 판을 모른다 | 달라진 줄 |
| 승인 화면 뒤 달라짐 | 물을 때의 판과 다른데 답으로 설명되지 않는다 | 달라진 줄 |
| 승인 뒤 달라짐 | 찍은 뒤 넣는 절이 바뀌었다 | 달라진 줄 |
| 승인 없이 들어감 | 해시가 없거나 표 밖의 `docs/` 변경이다 | 달라진 줄 |
| 같은 절 두 곳 | 두 쪽이 같은 절을 다르게 고쳤다. 그 파일은 넣지 않고 종료 3 | 절마다 `이번 실행`, `프로젝트`의 줄 |
| 아직 넣지 않음 | 코드 폴더의 글이 넣을 글과 다르다 | 파일 이름 |
| 넣은 뒤 달라짐 | 넣은 문서를 그 뒤 손으로 고쳤다 | 달라진 줄 |
| 넣지 않고 뺌 | 사람이 뺐다. 정본은 실행 폴더에 남는다 | 파일 이름 |

결정 기록은 제목, 위험·미확인 목록은 건수, 생성물은 줄 수만 리뷰에 오른다. HTML과 같은 제목의 절이 있는 문서는 파일 전체가 한 절이다. 다시 돌려도 결과가 같다. 흐름 문서의 결정·흐름도 밖 절과 프로젝트 용어집의 줄은 지우지 않는다. 개요 「용어」는 용어집에 줄을 더하기만 한다.

**같은 절 두 곳**: CI 앞에서 메인이 바로 묻는다. CI가 한 번으로 끝난다. 화면에 리뷰의 양쪽 줄을 싣고 선택지는 `이번 실행` / `프로젝트` / `그 문서를 뺌`이다. 답을 `task_set.py {실행 폴더} {id} --record "같은 절 두 곳|{쪽}|{원문}"`으로 적고 `--insert {코드 폴더} --take "{문서}#{절}={쪽}"`으로 반영한다. 머리글은 `(머리글)`, 파일 전체는 `(파일 전체)`, 빼기는 `{문서}#(파일 전체)=뺌`이다. 모르는 절이나 값은 종료 2다. 둘을 손으로 합치라는 답은 산출물을 바꾸는 답이다. 풀리지 않으면 `진행 stage=실행` 전이가 거부된다.

**다시 넣기**: 실행 승인 화면에 `아직 넣지 않음`이 있거나 답이 문서를 바꾸면 이 차례로 돈다.
1. 승인대기면 `task_set.py {실행 폴더} {id} --status 자체검증 --archive-judge --unlisted "다시 넣기"`로 물러난다. 이미 `stage=실행`이어도 넣는 줄을 돌리기 전이면 같다.
2. `--insert {코드 폴더}`(같은 절 두 곳이면 위 절차).
3. 문서 커밋, 읽기 판정(표가 바뀌었다), 최종 CI, `--wrap-review`.
4. `--status 승인대기 stage=실행승인 external_progress=`로 다시 묻는다. 새 답이 넣는 끝을 얼린다. 앞서 얼렸으면 `exec.py {실행 폴더} {id} --freeze --point 실행승인 --refreeze`까지 한다.

마무리 작성자가 직접 쓰는 것:
- `docs/decisions/{번호}-{제목}.md`: 사용자 결정과 되돌리기 비싼 알릴 결정. 첫 줄이 `# 제목`이다.
- `docs/operations/unverified.md`: 위험·미확인 가운데 성질이 붙은 항목과 배포 뒤 확인만 `- ` 줄로. 나머지는 실행 폴더에 남긴다.
- 넣은 작성 문서마다 결과 「본문」에 `- 지키는 경로: {문서} | {경로 패턴, 쉼표로}`.
- 생성 명령이 없으면 결과 「본문」에 `- 생성 명령 제안: {이름} | {명령} | {대상}`. 5절.

닫힌 항목은 메인이 `--close "{줄}"`로 상태 파일에 두고, 다음 넣기가 문서에서 함께 지운다. 상태 파일에서는 내보낸 뒤에 지운다. 마무리 뒤의 쓰기로 커밋을 따로 만들지 않는다.

테스트 지도 `docs/generated/test-map.md`는 누적 갱신이다: 지난 판 위에 이번 실행 코드 task 「변이 확인 지시」의 인수 기준과 시험 파일을 더하고, 시험 파일이 사라진 행만 지운다.
