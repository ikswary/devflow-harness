# 프로젝트 정찰

메인이 읽는다(새 실행의 정찰). 읽는 kind: 없음.

대상 프로젝트는 스택이 제각각이다. task마다 따로 구조를 파악하면 결과가 어긋나므로, 실행 초기에 한 번 정찰해 `recon.md`를 모든 task의 공통 기준으로 삼는다.

## 절차

1. 스크립트를 실행한다.
   ```bash
   bash "scripts/detect-stack.sh" "<프로젝트 경로>"
   ```
2. 출력을 `recon.md`에 저장하고, 아래 「사람이 채울 항목」을 코드를 읽어 덧붙인다.
3. 스크립트가 감지하지 못한 것은 "미확인"으로 적는다. 추측으로 채우면 뒤 task가 틀린 명령을 실행한다.

## 사람이 채울 항목 (스크립트 출력 뒤에 추가)

- **아키텍처 요약**: 패키지 구조(레이어드/헥사고날/모듈형), 대표 흐름 하나(예: Controller → Service → Repository)의 실제 파일 경로
- **코드 관례**: 예외 처리 방식, DTO·엔티티 명명, 테스트 스타일(JUnit5/Kotest/MockK/Mockito, pytest fixture 등), 로깅 방식 — 대표 파일 1~2개를 읽고 판단
- **검증된 명령**: 빌드 명령을 실제로 한 번 실행해 되는지 확인했다면 "검증됨"으로 표시. 시간이 오래 걸리면 생략하고 "미검증"
- **주의 사항**: 프로젝트 `CLAUDE.md`/`AGENTS.md`에 있는 규칙 요약

## Windows 환경 메모

- Bash 도구는 Git Bash다. `./gradlew`가 동작한다. PowerShell이라면 `.\gradlew.bat`.
- 경로에 한글이 있으면 반드시 따옴표로 감싼다.
- 멀티 모듈 Gradle 저장소는 루트에 `settings.gradle*`가 없을 수 있다(예: 모듈마다 독립 프로젝트). 이 경우 모듈마다 명령을 따로 적는다.
