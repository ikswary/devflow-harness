# 프로젝트 정찰

메인이 읽는다(새 실행의 정찰). 읽는 kind: 없음.

대상 프로젝트는 스택이 제각각이다. task마다 따로 구조를 파악하면 결과가 어긋나므로, 실행 초기에 한 번 정찰해 `recon.md`를 모든 task의 공통 기준으로 삼는다.

## 절차

1. 스크립트를 실행한다.
   ```bash
   bash "scripts/detect-stack.sh" "<프로젝트 경로>"
   ```
2. 출력을 `recon.md`에 저장하고, 아래 「사람이 채울 항목」을 코드를 읽어 덧붙인다.
3. 스크립트가 감지하지 못한 것은 "미확인"으로 적는다. 추측으로 채우면 뒤 task가 틀린 명령을 실행한다.

## 사람이 채울 항목 (스크립트 출력 뒤에 추가)

- **아키텍처 요약**: 패키지 구조(레이어드/헥사고날/모듈형), 대표 흐름 하나(예: Controller → Service → Repository)의 실제 파일 경로
- **코드 관례**: 예외 처리 방식, DTO·엔티티 명명, 테스트 스타일(JUnit5/Kotest/MockK/Mockito, pytest fixture 등), 로깅 방식 — 대표 파일 1~2개를 읽고 판단
- **검증된 명령**: 빌드 명령을 실제로 한 번 실행해 되는지 확인했다면 "검증됨"으로 표시. 시간이 오래 걸리면 생략하고 "미검증"
- **저장소 제약**: 파일을 고치면 걸리는 검사(문서·파일 크기 상한, 읽기·출력 예산 시험, 등록표·목록 대조 시험, 생성물 재생성 규칙)를 `| 파일 꼴(경로·glob) | 그 파일을 읽는 시험·검사 | 상한 | 지금 값과 여유 | 확인 명령 |` 표로 쓴다. 고칠 파일에서 걸리는 시험을 찾는 역참조이므로 시험마다가 아니라 파일 꼴마다 한 행이다. 시험 코드의 상수·목록에서 찾는다. 없으면 `없음`
- **주의 사항**: 프로젝트 `CLAUDE.md`/`AGENTS.md`에 있는 규칙 요약

## 경로 목록

스크립트 출력의 「경로 단서」를 프로젝트 설정 `_workspace\devflow-harness.project.md`의 절 `## 경로 목록`에 옮긴다. 네 줄 `- 감지한 실행: {이 실행 폴더 이름}`, `- 화면 경로: {패턴, …}`, `- 인프라 경로: …`, `- 문서 경로: …`(후보가 없으면 `없음`)로 쓴다. 절이 이미 있으면 값이 있는 줄은 고치지 않는다(사용자가 고친 값이 남는다). `없음`인 줄만 이번 실행의 후보로 다시 채우고, 채웠으면 `감지한 실행`을 이번 실행으로 적는다. 사용자에게 묻지 않는다. 그 실행의 첫 승인 화면이 이 목록을 알리고, 틀렸으면 사용자가 그 답에서 고친다.

절에 `- 운영 표지: {프로젝트 ref, 호스트, 비밀 파일 경로 패턴, …}`을 둘 수 있다. 명령이나 판정 파일에 걸리면 운영이고, 비어 있으면 위임 중에 밖으로 나가는 명령을 사람에게 묻는다. 두 줄도 더 둘 수 있다: `- 보안 신호 경로: {패턴, …}`, `- 보안 신호 낱말: {낱말, …}`. 코드 확인이 제품 변경분을 대조하는 값이고 올리는 데만 쓴다. 낱말 줄이 없으면 시작값(권한 부여 SQL, 인증 함수, 응답 헤더, CORS, 쿠키, 개인정보 칸 이름)을 쓰고, `없음`이면 낱말로 올리지 않는다. 이 프로젝트의 권한 함수나 정책 폴더를 알면 적는다.

스크립트 출력의 「시험 변화 경로 단서」는 같은 규칙으로 절 `## 시험 변화 경로`에 옮긴다: `- 시험을 돌리는 곳: …`, `- 정답 경로: …`, `- 시험 도우미 경로: …`.

## 저장소가 아닌 프로젝트

`git rev-parse`가 실패하면 `recon.md`에 `저장소: 없음`을 적고, git이 필요한 시작 단계(`_workspace/` 제외 목록 등록, 원래 폴더의 `git status`, 개발 기준 브랜치, 줄 끝 고정, 작업 폴더, 기준선)를 저장소 준비 뒤로 미룬다. 저장소 준비(`git init`, 첫 커밋에 넣을 파일과 무시 목록, 첫 커밋)는 첫 코드 폴더를 만들기 전에 명령마다 묻는다: 명령 그대로, 닿는 곳, 되돌리는 방법.

## Windows 환경 메모

- Bash 도구는 Git Bash다. `./gradlew`가 동작한다. PowerShell이라면 `.\gradlew.bat`.
- 경로에 한글이 있으면 반드시 따옴표로 감싼다.
- 멀티 모듈 Gradle 저장소는 루트에 `settings.gradle*`가 없을 수 있다(예: 모듈마다 독립 프로젝트). 이 경우 모듈마다 명령을 따로 적는다.

**작업 칸의 표지**: 로컬 런타임, 포트, 잠금이 폴더마다 따로임을 코드에서 확인했을 때만 `recon.md`에 `- 런타임: 폴더별`을 적는다(확인한 파일과 함께). 확인하지 못했으면 적지 않는다. 칸 수 2 이상은 이 표지가 있어야 고른다(`references/main/slots.md`). 의존성 목록 파일이 흔한 이름 밖이면 `- 의존성 목록: a, b`를 적는다.
