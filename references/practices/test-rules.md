# 시험 작성 기준

읽는 kind: `question`, `root-cause`, `ui-design`, `design`, `implementation`, `fix`, `change`, `flow-verify`, `reverify`, `full-verify`.

시험은 "틀린 코드에서 실패한다"를 보이려고 쓴다. 통과했다는 사실만으로는 아무것도 증명되지 않는다. 아래 일곱 가지는 이 원리를 어기는 대표적인 모양이다.

- **적용 범위**: 이번 변경이 더하거나 고친 시험에만 적용한다. 기존 시험의 위반은 지적하지 않고 「건수만」이나 백로그 후보로 둔다.
- **사용자 결정으로 받아들인 예외**: 시험 주석에 결정 번호가 있는 예외는 지적하지 않는다.
- **읽는 이**: 설계·구현·원인 분석 작성자, 그 task의 읽기 판정자, 검증 작성자가 읽는다.

## ① 확인 하나는 그것을 깰 수 있는 가장 낮은 계층에서 한 번
- 계층마다 맡는 확인은 다음과 같다.
  - 값·경계·분기: 단위
  - DB 제약·권한: DB 계층
  - 계층 사이 연결(이벤트 배선, 실제로 숨겨짐, 저장·전송 경로): E2E에서 대표 입력 하나로
- 새 E2E를 더하기 전에 같은 단언이 낮은 계층에 있는지 찾는다. 높은 계층은 느리고, 실패했을 때 원인 범위가 넓다.
- 인수 기준 문장이 "모든 X에서"인데 X마다 반복하지 않고 계층의 합으로 지키려 하면, 이것은 인수 기준을 해석하는 일이다. 설계의 「정해 주실 것」으로 올린다.
- 답이 계층 합이면 그 시험에 주석을 남긴다: "AC-nn의 어느 부분, 나머지는 {파일}, 결정 {번호}".

## ② 단언은 틀린 결과와 구분될 만큼 좁게
- 거부·오류는 기대한 코드(SQLSTATE, HTTP 상태, 앱 오류 코드)로 단언한다. "400 이상", "어떤 오류든"으로 받지 않는다.
- 부정 단언("X가 아니다", "보이지 않는다")에는 같은 조건의 양성 대조나 형·존재 확인을 함께 둔다.
- 화면 문구는 제품 상수를 가져와 쓴다. 시험 안에 사본을 두지 않는다.
- 여러 경로 가운데 하나를 받는 단언(`a|b`)은 경로를 고정할 수 있으면 고정한다.
- 산출물(그림, 파일, 메일)은 내용을 확인한다. 대리 값(DOM 글자, 크기)만 볼 수밖에 없으면 시험 제목과 결과의 「확인 안 된 것」에 "대리 확인"이라고 적는다.

## ③ 시간을 기다리지 말고 조건을 기다린다
- 고정 sleep과 고정 대기를 쓰지 않는다.
- 캐시 만료, 요청 제한 시간 같은 시간 값은 시험에서 주입하거나 가짜 타이머를 쓴다.
- "일어나지 않음"을 보는 관찰 창은 조작마다 두지 않고 마지막에 한 번만 둔다.

## ④ 흔들림을 흡수하는 장치는 원인에만, 표준 명령에 보이는 기록과 함께
- 판정을 느슨하게 하는 장치(재시도, 제한 시간 늘림, 건너뜀, 허용 범위 넓힘)는 원인 오류의 종류(연결 한도, 연결 시간 초과 등)에만 건다. 값 단언 실패에는 걸지 않는다. 경쟁·동시성 시험에는 걸지 않는다.
- 재시도가 일어나면 시험 이름이 남는 장치를 같은 변경에 넣는다.
- 그 기록이 recon에 적힌 그 계층의 **표준 명령을 에이전트 환경에서 그대로 돌린 출력**(또는 그 명령이 쓰는 결과 파일)에 보이는지 한 번 확인한다. 특수 플래그를 붙여야만 보인다면 장치가 아니다.
- 확인한 방법은 recon 「재시도 기록」에 남긴다.

## ⑤ 공유 상태는 자기 표식으로만 세고, 만든 것은 지운다
- 공유 DB·저장소에서 표·뷰 전체 개수를 전후로 비교하지 않는다. 시험이 붙인 표식(접두어, 시험 IP, 실행 id)으로 범위를 좁힌다.
- 시험이 만든 행·파일은 시험이 지운다. 정리 훅은 시험이 실패해도 돌게 둔다.
- 공유 자원을 바꾸는 시험은 다음 실행이 시작할 때 원래 상태인지 확인한다.

## ⑥ 전제가 없으면 시작할 때 이유를 말하고 실패한다
- 시험이 기대는 준비(설치, 빌드 산출물, 로컬 시험 자료, 마이그레이션)를 시작 지점에서 확인한다.
- 없으면 무엇이 없고 어떤 명령으로 준비하는지를 한 줄로 내고 실패한다.
- 건너뛰기로 녹색 종료하게 두지 않는다. 시간 초과로 늦게 드러나게 두지도 않는다.

## ⑦ 확인 도구는 정상일 때 "정상"이라고 말해야 한다
- 정답 파일이나 기준본을 대조하는 도구가 정상 상태에서도 늘 같은 경고를 내면 새 차이가 묻힌다.
- 의도된 차이는 목록으로 먼저 적용하고 나머지만 보고하게 만든다.
- 정답 파일을 바꾸는 변경은 그 대조 결과를 남긴다.

## 덧붙임
- 같은 조작 도우미를 새로 만들기 전에 기존 도우미를 찾아 쓴다.
- 외부 서비스 대역은 실제 로딩 경로(스크립트 로드, CSP)를 타는 방식으로 둔다.
