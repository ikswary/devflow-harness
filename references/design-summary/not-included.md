## 넣지 않은 것

아직 넣지 않은 것과 넣는 신호:

| 넣지 않은 것 | 넣는 신호 |
|---|---|
| 배포 준비 task(첫 환경 만들기: 자원 생성, 도메인, 첫 배포) | 환경이 없는 곳에 처음 배포하는 요청이 올 때. 「결정과 대안」의 배포 줄. 배포 계획·실행은 2026-10-06에 넣음 |
| 전체 검증의 종합 task | 관점이 넷을 넘거나 관점 사이에 겹치는 지적이 나오면. 그 전에는 마무리가 추적표를 모은다 |
| 줄 수 중앙값 조건, 새로 내보낸 이름 대조 | 같은 난이도의 끝난 task가 다섯 개 쌓이면 / 숨은 예외 기록에 이름 불일치가 나오면 |
| 스스로 줄이는 조건 중 컨텍스트 문턱 | 작성 에이전트 하나가 250K를 넘는 기록이 나오면 |
| 통합 흐름(어느 기능에도 넣지 못한 인수 기준의 테스트) | 요구사항 개요의 "기능 사이" 목록에 항목이 나오면 |
| 영향 후보 뽑기 스크립트, 지표 집계 스크립트 | 변경 task가 한 실행에 셋을 넘으면 / 첫 실행이 끝난 뒤 |
| 리뷰(이미 있는 변경)로 시작 | 그런 요청이 올 때. 「결정과 대안」의 검증·시작 task 줄. 배포만·동작을 바꾸지 않는 변경으로 시작은 2026-10-06에 0절 표로 넣음 |
| 전체 검증 관점 사이 겹치는 지적 접기 | 전체 검증에서 같은 파일·줄의 지적이 두 관점에서 나오면 |
| 실행 화면 캡처 판정(구현 뒤 Playwright·Roborazzi 등으로 화면을 찍어 승인 화면에 붙임) | 화면 있는 구현 task의 흐름별 검증에서 "써 볼 방법"이 승인 화면에 연속 세 번 올라오거나, 프로젝트에 캡처 도구가 이미 있을 때 |
| 화면 설계 전용 에이전트 `devflow-harness:ui-writer`(지금은 `devflow-harness:design-writer`가 `ui-design`을 맡음) | 화면 설계의 첫 판정 실패 이유가 "구성 요소부터 씀"(소프트웨어 설계 습관)으로 두 실행에서 반복될 때 |
| 디자인 시스템을 코드로 만드는 task(토큰·컴포넌트) | 같은 프로젝트의 두 실행 이상에서 `ui\common.md` 규약이 반복될 때(그때는 그 프로젝트의 구현 task) |
