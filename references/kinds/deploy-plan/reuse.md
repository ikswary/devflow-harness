# 배포 계획 task: 항목별 재사용

읽는 때: 1.2.0부터 시작한 실행의 배포 계획 task를 쓰거나 판정할 때. `tasks\{id}\reuse.md`의 `decision`이 `처음부터`면 「처음부터 쓸 때」만 읽고, `재사용`이면 그 아래를 읽는다.

절차서(`_workspace\policies\deploy\{환경}.md`)는 환경마다 따로이고 항목은 명령 줄 C, 되돌리기 줄 R, 사전 조건 P, 공통 배포 뒤 확인 V다. 설명 글은 재사용하지 않는다. 항목마다 그 항목이 인용한 근거가 묶여 있다(문서의 절이나 줄을 인용했으면 그 절만). 기계가 항목마다 가른다: 근거가 저장 커밋 뒤 바뀌었거나 근거를 읽지 못한 항목만 `다시 쓸 것`이고, 나머지는 스크립트가 값만 넣어 그대로 쓴다. 처음부터 쓰는 것은 절차서가 없거나 손상됐을 때, 환경이나 올릴 커밋을 읽지 못했을 때, 사람이 지시했을 때(메인이 `deploy_reuse.py {실행 폴더} {id} --fresh "이유"`)뿐이다.

## 처음부터 쓸 때
모듈대로 쓰고 다음 배포에도 그대로 돌 것을 표시한다. 표시가 없으면 이번 실행 몫이라 절차서에 남지 않는다. 일회성 마이그레이션, 앞 task 이야기, 이번 값이 든 글은 표시하지 않는다.
- 본문 `### 고정 항목`: `- 명령 1~3: 읽기`, `- 명령 11: 쓰기 | 근거 파일`, `- 되돌리기 1: 쓰기`. 번호는 얼리는 줄의 차례다. 종류를 적지 않으면 쓰기다. 읽기는 원격과 파일을 바꾸지 않는 줄과 HEAD만 옮기는 줄(`git checkout`, `git fetch`)이다.
- 사전 조건과 배포 뒤 확인의 행: 맨 앞이나 칸 안에 `[고정]`을 붙인다. 닫는 인수 기준이 적힌 확인은 남지 않는다.
- 명령마다 근거를 「명령 목록과 근거」나 `고정 항목` 줄에 인용한다. 실제로 기댄 곳만 적는다(`docs/deploy.md:7.2`). 그 인용에만 묶인다.

## 작성자 몫
모듈의 「하는 일」과 `result.md` 대신 `tasks\{id}\own.md` 하나를 쓰고 `python ${CLAUDE_PLUGIN_ROOT}/scripts/deploy_reuse.py {실행 폴더} {id} --compose`로 `result.md`를 만든다. 거부되면 이유대로 고쳐 다시 돌린다. `result.md`를 손으로 고치지 않고 `다시 쓸 것`이 아닌 항목을 고치지 않는다. `reuse.md`가 다시 쓸 항목과 이유, 알림, 재사용 항목을 보여 준다. 글에서 다른 명령을 가리킬 때는 `명령 {{줄:C4}}`처럼 항목 id로 쓴다. 조립 때 실제 번호가 들어가고, `명령 4`나 `4번째 줄`처럼 숫자를 쓰면 거부된다(추가 명령과 더하고 뺀 항목으로 번호가 밀린다). 「다시 쓴 항목」, 「더한 항목」의 번호는 스크립트가 묶는다.

필수 절(제목 수준 2, 없으면 `없음`):
- `올릴 커밋`: 「하는 일」 1의 전체 해시.
- `되돌릴 수 없는 단계`: 이번 답을 적는다. 지난 계획의 글은 `reuse.md`에 참고로 있고 이어지지 않는다.
- `배포 전 확인`: 배포 메모의 "배포 전 확인"을 모두 옮긴다. 재사용 항목에 이미 있으면 그 id를 적는다. 뒤 환경이면 앞 환경 실행의 사전 조건(`references/kinds/deploy-plan/multi-env.md`)을 맨 앞에 쓴다.
- `배포 뒤 확인`: 닫는 인수 기준의 번호와 확인. 읽기와 쓰기를 나누고 실행 판정이 돌릴 것과 사람이 볼 것을 나눈다.
- `미룬 실물 확인`: 배포 메모의 미룬 실물 확인. 사람이 볼 것이다.
- `배포 뒤 적을 문서`: 「하는 일」 8과 같다.

`다시 쓴 항목`: 다시 쓸 항목마다 빠짐없이 `### {id}` 한 칸(뺄 항목은 빼고). 첫 줄은 `근거: 파일:줄, 파일`이다. `근거: 없음`은 글, 읽기 줄, git 줄만 받는다. 다음 가운데 하나를 쓴다.
- 새 값: 명령은 `cmd` 울타리에 한 줄, 그 밖은 글 한 줄. 커밋, 폴더, 다른 명령의 번호는 실제 값으로 써도 스크립트가 자리 값으로 바꾼다. 지난 실행의 task id가 남으면 거부된다.
- `그대로: 이유`: 근거를 읽어 보니 고칠 것이 없을 때.

있을 때만 쓰는 절:
- `뺄 항목`: `- C5: 이유`. 낡은 항목을 뺀다(재사용 항목도 된다). 머리와 「알릴 것」에 늘 보이고 다음 절차서에 남지 않는다. 뺀 줄을 번호로 가리키는 항목이 있으면 함께 고치거나 뺀다.
- `더한 항목`: `### A1 | 절 이름 | C5 앞`(자리는 있어도 없어도 된다). `근거:` 줄, 명령이면 `종류: 읽기`나 `종류: 쓰기`, 새 값. 새 자원이나 새 배포 방식의 몫, `reuse.md` 알림의 바뀐 절에서 나온 단계가 여기로 온다. 다음 절차서에 남는다.
- `추가 명령`: 이번에만 필요한 명령(`cmd` 울타리). 고정 명령 앞에 놓이고 다음 절차서에 남지 않는다.
- `설명`, `연결 경로 대조`, `멈추는 조건`: 본문에 그대로 들어간다. 운영이면 `연결 경로 대조`를 쓴다.
- `정해 주실 것`, `하실 일`, `알릴 것`, `확인 안 된 것`, `답하신 것의 반영`: 이번 실행에서 생긴 항목. `cmd` 울타리는 쓰지 못한다.
- `자식`: `closes_ac:`, `partial_ac:`, `depends_on:`(뒤 환경이면 앞 환경 계획 id, 같은 실행에 앞 환경 계획이 있으면 필수), `판정 기준:` 줄.

## 승인 화면
사람 승인은 그대로다. 알림이나 위임으로 닫지 않는다. `screen.py`가 머리에 "재사용 N, 다시 씀 k(근거 바뀜 a, 그 밖 b), 이번 실행 몫 m"과 더한 수, 뺀 항목, 알림을 싣는다. 명령과 되돌리기는 접지 않고 번호와 표시(`재사용`, `다시 씀`, `더함`, `이번만`, `달라짐`)를 붙여 모두 보인다. 번호는 얼리는 줄의 번호다. 재사용하는 배포 뒤 확인은 「알릴 것」에 모두 싣고, 리뷰 자료가 다시 쓴 항목의 앞 판과의 차이를 보인다.

## 자체 검증 (읽기 판정)
모듈의 「자체 검증」 대신 다시 쓴 항목, 이번 실행 몫, 값 치환만 본다. 재사용 항목은 다시 읽지 않는다.
1. `deploy_reuse.py {실행 폴더} {id} --check`가 통과한다(값 치환, 재사용 항목의 근거 해시, 절차서 대조). 출력의 값이 머리 파일과 마무리의 커밋, 폴더와 같다. `달라진 재사용 항목`은 실패가 아니며 사람에게 올라간다.
2. 다시 쓴 항목과 더한 항목마다: 모듈 기준 1(근거가 실재하고 승인된 배포 방식과 맞음, 대화형 입력을 채운 줄이 없음)을 본다. `그대로`면 바뀐 근거를 읽어 그 이유가 맞는지 본다. 「뺄 항목」은 그 절차가 정말 필요 없는지 본다. `reuse.md`의 바뀐 절 알림은 읽어 더할 단계가 빠지지 않았는지 본다.
3. 모듈 기준 2: 배포 메모의 배포 전 확인과 미룬 실물 확인이 `own.md`에 빠짐없이 있다(마무리 결과와 대조).
4. 닫는 인수 기준마다 배포 뒤 확인이 있다. 운영이면 쓰기 확인이 없다(「정해 주실 것」으로 올린 것 제외). 뒤 환경이면 `references/kinds/deploy-plan/multi-env.md` 기준 9를 본다.
5. 추가 명령마다 근거가 실재한다. `되돌릴 수 없는 단계`가 다시 쓰고 더한 쓰기 줄과 맞다.
6. 모듈 기준 6, 8: 비밀값이 없고, 배포 뒤 적을 문서가 설계의 줄이나 배포 메모와 같다.

실행 판정, 배포 대상 동일성 관문(`없음(소스 시험)`), 명령 얼림은 재사용과 상관없이 그대로다.
