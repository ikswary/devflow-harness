# 검증 task: 메인 순서

읽는 때: 메인이 검증 task(`flow-verify`·`full-verify`·`reverify`)를 다룰 때.

- 흐름별 검증·재검증·수정 흐름 합치기를 띄우기 전에 `collect.py {실행 폴더} {task 폴더} --notified {흐름}`로 그 흐름에서 알림으로 지나간 task의 알릴 것·확인 안 된 것을 파일로 뽑는다.
- 신규 1.0.2 실행이 A를 명시적으로 선택했고 `shadow-plan.json`이 유효할 때만 일반 검증 전에 `references/experiments/verification-shadow-a.md`의 candidate → baseline → current → final 순서를 실행한다. 각 단계는 서로 다른 instance가 한 번 반환하며 `collect.py --shadow-open/--shadow-freeze/--shadow-check` 성공 뒤 다음 단계로 간다. 실패·격리 불명은 비교에서 제외하고 current·final의 기존 gate는 그대로 수행한다.
- **수정 세대**: `spawn_children.py`가 센다(재검증이 낸 수정은 그 재검증이 의존하는 수정의 최대 세대 + 1). 상한(시작값 2)에 닿은 재검증은 `screen.py`가 「정해 주실 것」에 (가) 만들기 / (나) 백로그 / (다) 설계 변경으로 올리고, 메인은 답대로 `--over-cap`(백로그면 `--over-cap 백로그`)이나 변경 task로 한다.
- 흐름별 검증을 띄우기 전에 그 흐름에 화면 구현 task(`fe-implementation`)가 있으면 `task_set.py {실행 폴더} {id} --add "범위|실물 확인: 이 흐름에 화면 구현 task 있음"`. 그 항목은 승인 뒤에도 `waiting_user`에 적지 않는다. `미룸`은 답의 표지대로.
- 새 지적이 없으면 작성자가 이 task의 항목을 비우고 옮긴 `[T0xx]` 줄만 두며, 재검증은 알림으로 끝난다.

## 흐름 리뷰

1.2.0부터 시작한 흐름별 검증은 실행 판정 → 읽기 판정 차례다. 그 앞에 시작한 task는 실행 판정을 띄우지 않는다. 실행 판정을 다시 돌렸으면 읽기 판정도 다시 띄운다.
- 작성자가 반환하면 `screen.py {실행 폴더} {id} --flow-commands` 출력을 `전·후 명령:`으로 넣어 `xjudge-{id}`를 그 흐름의 폴더에서 띄운다.
- `돌리지 못함`의 `새 명령이 필요함`이 밖에 닿거나 `권한 거부`면 탐침의 명령 단계로 묻는다. 그 전에는 돌리지 못한 채로 승인 화면에 간다.
- 코드 확인 뒤 지금 화면을 내고 `visual.py` 출력을 붙인다. `이의`면 `--answer`가 찍은 `--record`와 고침 task를 먼저 한다. 없으면 닫지 못하고, 합치기가 그 task를 기다린다.

## 코드 확인

1.2.0부터 시작한 흐름별 검증에서 승인을 묻기 전, 카드의 답을 받는 턴, `답 대기` 줄이 보일 때 따른다.

사람이 구현의 판단을 코드로 보는 자리다. 카드는 한 턴에 한 장을 일반 메시지로 내고 턴을 끝낸다. `AskUserQuestion`을 쓰지 않는다(모바일에서 앞선 본문과 코드가 보이지 않는다). 추천을 달지 않는다. 구조, 데이터, 트랜잭션, 오류, 외부호출, 보안 판단과 판단 없는 보안 코드만 곳이 되고, 동작은 흐름 리뷰, 시험은 시험 변화로 간다.

**순서**
1. 읽기 판정이 통과하면 `screen.py {실행 폴더} {id} --places`를 돌린다. 곳을 묶어 `tasks\{id}\places.md`에 고정하고 그 뒤로는 이 파일만 읽는다.
2. `task_set.py {실행 폴더} {id} --status 승인대기`.
3. `기다림`인 곳마다 차례로: `task_set.py {실행 폴더} {id} --card-open {키}`, `screen.py {실행 폴더} {id} --card {n}`. 출력을 고치지 않고 일반 메시지로 낸 뒤 턴을 끝낸다.
4. 답을 받으면 `screen.py {실행 폴더} {id} --answer "원문"`으로 푼다.
5. 기다리는 곳이 없거나 `task_set.py`가 `카드 끝`을 찍으면 지금 화면과 질문을 그대로 낸다(3절 「승인을 묻는 방법」, `--save`). 답이 빠진 곳이 있으면 `→완료`는 거부되고 `보류`는 받는다.

**답을 푼 출력**

| 출력 | 할 일 |
|---|---|
| `--record: …` | 그 값 그대로 `task_set.py {실행 폴더} {id} --record "…"`. 곳 답은 task 전체의 승인이 아니다 |
| `고침 task: …` | 위 기록 뒤 그 명령으로 수정 task를 만든다(`--place`가 머리를 쓴다) |
| `다시 보임: … --full` | 코드 약 60줄을 같은 카드로 다시 낸다 |
| `다시 보임: … --tree` | 그 판단 폴더의 파일과 줄 수 표를 앞에 붙여 같은 곳을 다시 묻는다. `되물음(이해)`로 적는다. 둘째 `판단 안 됨`은 남긴 곳이다 |
| `보류·중단: …` | 승인 답 표의 보류로 처리한다. 답 없는 곳이 있어도 받는다 |
| `되물음: …` (종료 3) | 해석하지 않고 다시 묻는다. 빈 `이 코드만 고침`, 빈 `판단 안 됨`, 답이 빠진 판단, 코드를 보이지 못한 카드의 `문제 없음`도 여기다 |

답은 `1 문제 없음`, `2 이 코드만 고침 : {무엇을}`, `3 판단 안 됨 {부족한 것}`, `4 나머지 남김`이다. 맨 숫자는 그 카드의 답 번호다. 판단이 여럿이면 `b1 1, b2 이 코드만 고침 : …`처럼 판단마다 받고, 판단을 말하지 않은 답은 그 곳 전체의 답이다. `나머지 남김`은 사람 답 한 줄이고 보안 곳에는 받지 않는다. 보안 곳이 남으면 계속 기다린다.

**가림**: 카드, `cards\{키}.shown.md`, 고친 코드의 화면, `places.md`의 지운 줄과 의견은 비밀값 꼴을 가린다. 지운 줄은 신호 줄에 `지운 줄:`로, 지운 파일은 커밋 앞의 코드로 싣는다.

**고친 코드**: `이 코드만 고침`의 수정 task는 `origin`이 `사용자 {T} {답 시각} 코드 확인 {키}`이고 알림으로 지나가지 않는다. 판정 통과 뒤 그 task의 승인 화면에 답 원문과 변경 발췌가 실리므로 코드로 다시 묻는다. 합치기는 그 수정을 기다리고, 재검증은 만들지 않는다.

**기다리는 동안**: 반환이 오면 반환만 처리한다. 다른 화면을 띄우지 않고 사람 앞에 끼어드는 말을 쓰지 않으며, 턴 끝에 `답 대기: T081 카드 2/5` 한 줄만 쓴다(`board.py --ready`가 그 줄을 낸다). 답 대기 중에는 `screen.py --save`가 거부된다. `/clear` 뒤에는 `screen.py {실행 폴더} {id} --card`가 열린 카드를 다시 낸다. 카드 사이에 끊겨 `코드 확인 남음:` 줄이 보이면 그 줄의 키로 다음 카드를 연다.

**위임**: 「이번 실행의 값」 `위임` 행의 층에 `L1`이 있으면 `--places`가 보안 밖의 곳을 `남김(위임)`으로 미리 적는다. 명령만 맡긴 실행(`L2~L3`)은 카드가 그대로 온다. 카드는 보안 곳만 낸다. 답 없는 시험 끄기·삭제 줄과 보안 곳은 위임 중에도 합치기 전에 기다린다.

**재지 못한 코드 task**: 커밋 값, 코드 폴더, git 때문에 곳이나 시험 변화를 재지 못한 task다. 차례는 이렇다.
1. 커밋 값이 비었으면 그 task의 커밋을 찾아 `task_set.py {실행 폴더} {T} commit={값}`으로 적거나, 코드를 바꾸지 않았으면 `no_change=true`로 표시한다. 찾지 못하면 값을 지어내지 않는다.
2. 코드 폴더가 없으면 `git worktree`로 그 브랜치를 다시 붙이거나 커밋으로 복구를 시도한다.
3. `screen.py {실행 폴더} {id} --places --remeasure --tried "{한 일}"`로 재지 못한 task, 고정 뒤 끝난 task, 커밋 바뀐 task만 다시 잰다. 새 곳은 위 순서로 묻는다. 커밋이 「건드릴 파일」과 겹치지 않으면 재지 못함이 남는다.
4. 그래도 남으면 출력의 「보지 못한 코드」 줄을 일반 메시지로 내고 답을 기다린다. 답은 task마다 한 번 `--record "코드 확인 재지 못함 {T}|합쳐도 됨|{원문}"`이고, 보안 신호와 시험 변화를 함께 푼다. 커밋을 고치면 3부터 다시 한다. 뜻은 "그 코드를 보지 않고 합쳐도 된다"이고 추천을 달지 않는다. `보류`는 받는다. 위임 중에도 기다리고, 빈 답과 위임의 말은 받지 않는다.

**차례**: 보안 곳이 앞이고 상한과 따로 센다. 보안 밖은 흐름당 5곳이고 넘친 곳은 `남김(상한)`이다.
