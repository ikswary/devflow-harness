# 검증 task: 실행 판정

읽는 때: 실행 판정자가 1.2.0부터 시작한 흐름별 검증의 전·후를 돌릴 때. 이 판정의 몫은 전·후뿐이다. 그 흐름의 표준 명령과 인수 기준 판정은 작성자와 읽기 판정자가 한다. 정의의 규칙 1, 3(독립 최종 검사, 변이 확인)과 프롬프트의 `돌릴 것`, `변이 확인`은 쓰지 않는다.

시나리오는 작성자의 `result.md` 「돌려 볼 시나리오」다. 결과는 `judge-run.md` 「흐름 리뷰 전·후」에 쓴다(꼴은 `judge-run-file`). 고르지 않고, 바꾸지 않고, 해석하지 않는다. 고른 시나리오가 없으면 절에 `- 없음`을 쓴다.

**돌리는 규칙**: 시험 실행과 같은 규칙이다. 프롬프트 `전·후 명령`의 원천(`recon.md`, 승인된 실행 전체 설계)과 그 흐름의 시험 파일로, `recon.md` 「공유 자원과 잠금」의 잠금 그대로 돌린다. 시험이 이미 쓰는 dev 공유 자원은 같은 조건으로 쓴다.
- 그 밖의 새 명령은 실행 폴더와 임시 폴더 안에서 끝나고 연결 대상 환경 변수를 비우거나 시험값으로 고정한 것만 돌리고 `명령:`에 적는다. 하네스가 소유하지 않은 곳에 닿으면 돌리지 않고 `돌리지 못함: 새 명령이 필요함 | {명령과 닿는 곳}`이다. 메인이 명령 단계로 보낸다.
- 명령이나 환경 변수에 프로젝트 설정 `운영 표지`가 걸리면 돌리지 않는다.
- 프롬프트의 `검증 제외`에 걸린 시나리오는 돌리지 않고 `돌리지 못함: 사람 지시로 뺌 | {원문}`이다.

**전과 후**
- 프롬프트 `전·후 명령`의 `전:`이 갈라진 커밋과 `flow.md` 경로, `후:`가 흐름 폴더다. 후는 그 폴더에서 돌린다. 돌리기 전에 `git status --short`를 저장한다.
- 전은 갈라진 커밋을 임시 폴더(시스템 임시 폴더 아래 `{task id}`, `git worktree add`)로 꺼내 두 번째 런타임으로 돌린다. 임시 폴더는 쓰기 제한의 예외이고, 그 안에서 끝나는 의존성 설치는 위 "새 명령"의 규칙으로 돌린다. 포트는 후와 겹치지 않게 한다.
- 런타임을 폴더마다 나눌 수 없거나 전의 런타임이 뜨지 않으면 갈라진 커밋에서 같은 시나리오 시험을 돌린 실패 출력을 전으로 쓴다.
- 이 흐름이 바꾸기 전의 동작이 갈라진 커밋에 없으면(기존 사이트를 옮기는 실행) 기준본 실행을 전으로 쓴다. 기준본을 띄우는 것도 위 규칙을 따른다.
- API면 요청과 응답 발췌, 화면이면 `logs\`의 캡처(화면마다 한 장, `캡처:`에 task 폴더 기준 경로), 배치·도구면 명령과 출력이다. 사람 이름, 주소 같은 개인정보는 기계로 가리지 못하므로 발췌에서 뺀다.

**치우기**: 띄운 런타임을 모두 멈추고 `git worktree remove --force {폴더}`, `git worktree prune`을 돌린다. 못 치우면 `이상 신호`에 경로를 적는다. 끝에 흐름 폴더의 `git status --short`를 저장한 것과 대조하고, 다르면 남은 파일을 `이상 신호`에 적는다(합치기는 폴더가 비어야 돈다).

**돌리지 못하면** 이유는 다섯이다: 환경이 없음(배포 환경, 외부 서비스, 언어 모델 에이전트가 필요한 장면), 새 명령이 필요함, 사람 지시로 뺌, 런타임이 뜨지 않음(시험 출력으로도 전을 못 낼 때, 오류 첫 줄을 적음), 권한 거부(거부된 명령을 적고 반환에 `권한 거부:` 줄을 쓴다. 이 kind에서는 판정불가로 쓰지 않고 메인이 사람에게 묻는다). `대신:`에 시험이 무엇을 확인했는지 사용자 말로 쓴다. `돌리지 못함`은 실패가 아니라 `## 통과 못 한 기준`에 쓰지 않는다. 사람에게는 스크립트가 「확인 안 된 것」으로 올린다.

돌린 것이 없어도 판정 파일의 절은 모두 쓴다. `## 검사 입력과 독립 근거`는 `제품 commit/diff:`를 적고 나머지 이름 뒤에 `없음`을 적는다. 공유 자원 사용 중은 돌리지 못함이 아니라 자원 대기다.
