# 요구사항 상세 task (`req-detail`)

묶음 하나의 요구사항과 인수 기준을 쓴다. 이후 모든 task의 완료 판단이 이 인수 기준에 의존한다.

## 먼저 읽을 것
`${CLAUDE_PLUGIN_ROOT}/references/practices/requirements-spec.md`(인수 기준을 쓰는 기준), 정본 `spec\overview.md`, 기획 정본 `spec\brief.md`(이 묶음의 여정 단계·화면 id·정책·우선순위).

## 하는 일
1. 정본 `spec\{묶음}.md`를 쓴다: 기능 요구사항(번호, 개요 요구사항 번호와 **기획 정책 id**를 단다), 비기능 요구사항, 인수 기준(Given/When/Then, 번호, 화면이 있으면 화면 id), 범위 밖, 가정. 기획이 "뒤 단계·범위 밖"으로 둔 것은 쓰지 않는다. 기획 정책마다 FR·AC가 하나 이상 있어야 한다. 기획에 없는 정책이 필요하면 깔고 쓰지 않고 「정해 주실 것」(기획을 바꾸는 제안).
2. 기존 코드의 사실을 전제로 한 인수 기준과 가정에는 근거 위치(파일:줄)를 붙인다. 근거를 찾지 못한 사실 전제는 가정으로 내리고 「확인 안 된 것」에 올린다.
3. 사용자가 말하지 않았는데 채운 값(수치, 문구, 한도, 기본값)은 정본에 "담당이 채움"으로 표시한다. 화면 있음인 묶음(기획이 화면 설계 행을 둔 묶음)에서 **화면의 구성·배치·문구는 채우지 않는다**: FR·AC는 보이는 정보와 동작을 쓰고 대상은 개요 「용어」의 이름으로, 화면은 기획의 화면 id로 부른다(화면 설계 task가 요소·문구를 정한다. 같은 문구가 상세·화면 설계 두 승인 화면에 오르지 않게).
4. 비기능 요구사항에도 인수 기준을 달거나, 달지 않으면 "검증하지 않음"과 이유를 적는다.

## 승인 화면
- 정해 주실 것: 답이 없거나 서로 부딪치는 요구
- 알릴 것: 담당이 채운 값, 범위 밖으로 뺀 것
- 확인 안 된 것: 대조할 자료가 없는 사실 전제(틀리면 바뀌는 인수 기준, 확인할 task)
- 건수만: 사용자 답을 그대로 옮긴 인수 기준 수, 사실 대조를 마친 인수 기준 수

## 자식 목록
자식 kind: `design`

그 묶음의 설계 task 하나(`kind: design`, `flow`는 묶음 이름과 같게 시작한다. 설계가 흐름 지도로 바꿀 수 있다). **늘 쓴다**(화면 유무와 무관. 화면 유무 분류가 틀려도 설계 행이 고아가 되지 않게). 기획이 이 묶음에 화면 설계 행을 두었으면(메인이 프롬프트 「이번 지시에만 있는 것」으로 그 task id를 준다) `depends_on`에 그 id를 적고 범위에 "화면 정본 `ui\{묶음}.md`(채택 줄 포함)를 따른다"를 적는다. 공통이 아닌 묶음의 설계는 공통 묶음의 설계 task에 의존한다(공통 설계의 task id를 모르면 `depends_on`을 비우고 범위에 "공통 설계에 의존"을 적는다. 메인이 채운다).
상세를 쓰다 보니 기획의 화면 유무가 틀렸으면(화면 설계 행이 없는데 화면이 있다, 또는 그 반대) 「알릴 것」에 적는다. 메인이 화면 설계 task를 만들어 이 설계 task의 `depends_on`에 더하거나, 필요 없는 화면 설계 task를 `보류`로 닫는다.

## 자식 행 계약
없음

## 자체 검증 (읽기 판정)
1. 모든 기능 요구사항에 인수 기준이 하나 이상 연결됐다.
2. 인수 기준의 Then이 관찰 가능하다. 판정자가 인수 기준마다 테스트 이름과 단언 한 줄을 써 본다. 쓸 수 없으면 실패("적절히", "빠르게" 같은 말이 남아 있으면 실패).
3. 기존 코드를 전제로 한 인수 기준과 가정마다 근거 위치가 있고, 판정자가 **하나씩 전부** 열어 일치를 확인했다(표본으로 하지 않는다). 대조할 자료가 없는 것은 「확인 안 된 것」에 있는지 본다.
4. 담당이 채운 값이 빠짐없이 「알릴 것」에 있다(판정자가 정본의 수치·문구·기본값을 요청 원문과 답에서 찾아 본다).
5. 범위 밖 항목이 적혀 있다.
6. 기획 정본의 이 묶음 정책 id마다 FR·AC가 하나 이상 있고(판정자가 정책 id 집합과 FR이 단 정책 id 집합을 대조), 기획이 뒤 단계·범위 밖으로 둔 개요 요구사항 번호를 FR이 가리키지 않는다.

판정자의 권장 가운데 요구사항의 뜻을 바꾸는 것은 `judge.md` 「권장」에 대안 문장과 함께 적는다. 메인이 「정해 주실 것」으로 올린다.
