# 구현 task: 메인 순서

읽는 때: 메인이 구현 task(`implementation`)·화면 구현 task(`fe-implementation`)·서버 구현 task(`be-implementation`)·수정 task(`fix`)를 다룰 때. 화면·서버 구현의 메인 순서와 실행 판정도 이 파일과 같다.

- 구현·수정 task는 `screen.py`가 "알림 조건: 충족"(정해 주실 것·하실 일이 비고 통과 못 한 기준 없음)이고 자체 검증을 전부 통과하면 알림으로 지나간다. 알림 줄에 「알릴 것」「확인 안 된 것」의 건수를 붙이고(`T017 완료(알림): 알릴 것 3·확인 안 된 것 1, 흐름별 검증에서 모아 보여 드림`), 그 흐름의 흐름별 검증 승인 화면이 내용을 모아 올린다.
- **수정 task의 자리**: 아직 합쳐지지 않은 흐름의 코드는 그 흐름 폴더에서. 통합 브랜치에 이미 합쳐진 코드를 고치는 모든 task(전체 검증·마무리의 수정, 합쳐진 흐름에 대한 변경)는 수정 흐름(`fixes`, 통합 브랜치의 끝에서 갈라짐)에서 차례로. 흐름이 하나뿐인 실행은 그 흐름 폴더에서.
- 같은 흐름의 다음 구현 task를 띄우기 전에 `conventions.py`를 돌린다.
- 인프라 경로(프로젝트 설정 「경로 목록」)를 「건드릴 파일」에 둔 코드 task는 알림으로 지나가지 않는다(`screen.py`가 "알림 조건: 미충족(인프라 경로: …)"을 낸다).

자체 검증(메인이 이 순서로 한다. 3 읽기 판정이 볼 것과 4·5는 `references/practices/code-task.md` 「판정」, 2 실행 판정의 절차는 `references/kinds/implementation/run-check.md`):
1. **기계 대조**(메인): `task_set.py … --status 자체검증`이 `machine_check.py`를 돌려 `machine_check`에 적는다. 대상 밖 파일, 의존성·설정·마이그레이션 변경, 테스트 삭제·건너뜀. 걸리면(3) 읽기 판정을 한다.
   `machine_check.py` 출력의 `보안 신호:` 줄은 읽기 판정 프롬프트에 그대로 넣는다(판정자가 그 위치에도 `코드 의견:`을 쓴다).
3. 읽기 판정을 띄우는 조건(1.2.0부터 시작한 코드 task는 조건 없이 늘 띄운다. 아래는 그 앞에 시작한 task다):
   - 조건(구현 task): 머리 파일 `closes_ac`가 있다 / 1번 기계 대조에 걸렸다(`machine_check`가 3) / 결과의 「알릴 것」이 1개 이상이다. 수정 task와 화면 구현 task는 늘 읽기 판정을 받는다.
   - 서버 구현 task: 구현 task의 셋에 더해 머리 파일 「시그니처와 결정 번호」에 `[계약]`이 있으면.
   - 구현·서버 구현 task가 「건드릴 파일」에 화면 경로(프로젝트 설정 「경로 목록」)를 두면 읽기 판정을 한다(머리 파일의 "화면 동작을 바꾸는가" 기준을 본다).
   - 조건이 아니면 판정 표에 "해당 없음(조건 미충족)"으로 적는다. 「확인 안 된 것」에 올리지 않는다.
