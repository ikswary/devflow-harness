# 인프라 결정 task (`infra-design`)

기능 설계가 전제로 삼는 인프라 결정(자원·바인딩·요금제·외부 서비스·DB 마이그레이션 전략·배포 환경)을 기능 설계가 시작되기 전에 따로 받는다. 정본은 `design\infra.md`이고, 실행에 하나다. 알림으로 지나가지 않는다.

## 먼저 읽을 것
`${CLAUDE_PLUGIN_ROOT}/references/practices/design-doc.md`, `${CLAUDE_PLUGIN_ROOT}/references/practices/release-practice.md`(배포·되돌리기 절), `recon.md` 「배포 단서」·「공유 자원과 잠금」, 프로젝트 설정 「경로 목록」의 인프라 경로에 있는 설정 파일, 상세 정본들의 「인프라 전제」, 기획 정본(있으면). 시작 task로 왔으면(인프라만 바꾸는 요청) 요청 원문이 「인프라 전제」를 대신한다.

판정자: `${CLAUDE_PLUGIN_ROOT}/references/practices/design-doc.md`

## 하는 일
1. **결정 지도를 먼저 쓴다.** 결정 목록, 결정 사이의 의존, 사용자 결정 표시.
2. 정본 `design\infra.md`를 쓴다: 결정 기록(번호 `I-n`·선택지·선택·이유·종류), 자원·바인딩 목록(식별자는 있음/없음만), 마이그레이션 전략과 적용 순서, 환경별 차이, 확인 안 된 가정마다 확인 대상과 `[탐침]` 표시 또는 확인 task.
3. 결정마다 종류를 붙인다.
   - **사용자 결정**: 선택지에 따라 돈, 사용자가 할 일, 범위, 고객·운영자가 겪는 것이 달라지고, 요구사항과 이전 답으로 하나로 정해지지 않는다. 되돌릴 수 없는 자원 결정(데이터를 옮기거나 다시 만들어야 하는 것)은 늘 사용자 결정이다.
   - **알릴 결정**: 아래 질문에 하나라도 "예". 걸린 번호를 적는다.
     1. 바꾸려면 저장된 데이터나 만들어진 자원을 옮기거나 다시 만들어야 하는가.
     2. 저장소 밖에서 보이는가(주소, API 경로, 고객이나 운영자가 읽는 문구). 명령을 돌리는 사람의 화면에 새로 나오는 줄, 실패·경고 문구, 사용법·도움말 문구도 운영자가 읽는 문구다.
     3. 외부 서비스·계정·요금제를 새로 쓰거나 설정을 바꾸는가.
     4. 승인된 요구사항이나 이전 결정의 문구를 고쳐야 성립하는가(요구사항에 없던 것을 더하거나 빼면 알리는 것이 아니라 묻는다).
     5. 개인정보·비밀값·접근 권한이 놓이는 곳이나 범위를 바꾸는가.
     6. 사용자의 말을 해석해 적용 범위를 정했는가.
   - **관례 결정**: 따른 기존 코드·설정의 위치(파일:줄), 또는 다른 선택지가 어기는 인수 기준 번호를 댈 수 있을 때만. 못 대면 관례가 아니다.
4. 배포 계획 줄은 실행 전체 몫 설계가 이 정본을 따라 쓴다(이 task는 쓰지 않는다).

## 승인 화면
- 정해 주실 것: 사용자 결정(되돌릴 수 없는 자원 결정은 맨 앞에)
- 하실 일·허용 요청: 사용자만 할 수 있는 계정·콘솔·요금제 작업
- 알릴 것: 알릴 결정과 걸린 질문 번호
- 확인 안 된 것: 가정마다 확인 대상과 `[탐침]` 또는 확인 task
- 건수만: 관례 결정 수, 자원·바인딩 수

## 자식 목록
자식 kind: `probe`, `implementation`

- `[탐침]` 가정마다 `probe` 행: 범위 = 가정 번호·문장·참과 거짓을 가를 관찰, 판정 기준 = `references/kinds/probe.md` 「자체 검증」의 계획 단계.
- 기능 구현보다 먼저 들어가야 하는 인프라 경로 변경(마이그레이션 등)은 `implementation` 행: 흐름 이름, 「건드릴 파일」에 그 경로.

## 자식 행 계약
없음

## 자체 검증 (읽기 판정)
1. 상세 「인프라 전제」 줄(또는 요청 원문)마다 결정 번호나 「정해 주실 것」 항목이 있다.
2. 관례로 분류된 결정 전부에 질문 1~6을 다시 적용한다. 하나라도 "예"면 실패.
3. 가정마다 확인 대상과 `[탐침]` 또는 확인 task가 있고, `[탐침]`마다 자식 `probe` 행이 있다.
4. 되돌릴 수 없는 자원 결정(데이터를 옮기거나 다시 만들어야 하는 것)이 사용자 결정이다.
5. 운영 제약: 설계가 쓰는 설정·명령·배포 단계가 저장소의 배포 문서·정적 검사의 금지 규칙과 부딪치지 않는다. [RP-22]
6. 비밀값·인프라 식별자가 정본과 결과에 없다.
7. 선택지가 앞 단계 정본(개요·기획·요구사항 상세)의 문장을 바꾸면 선택지마다 앞 정본 줄(`result-file.md`)이 있고, 줄마다 `지금:`이 그 파일:줄에 있고 `바뀜:`이 같은 정본의 다른 줄(같은 번호의 FR·AC, 「용어」)과 부딪치지 않으며 같이 바뀔 줄이 모두 적혔다. [RP-23]
