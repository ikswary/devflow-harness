## 3. 승인과 알림

`screen.py {실행 폴더} {task id}`의 출력이 사람에게 가는 글의 재료다. 메인은 결과 본문을 읽지 않는다. 다만 묻는 task마다 화면의 항목 하나를 골라 결과 본문의 해당 절과 맞는지 **표본 대조**한다. 어긋나면 새 작성 에이전트에게 「승인 화면」 절을 고치게 한다.

**사람에게 가는 것**(1.3.0부터 시작한 task, `scripts/report.py`가 그린다)
- **알림 한 줄**(`알림: …`): 답을 기다리지 않는다(`approval_mode: 알림`, 상태 `완료`). 줄과 펼침 경로를 그대로 보인다. 어느 task가 어떤 조건에서 지나가는지는 등록표 `boundary`와 kind의 `main-order.md`. 조건이 하나라도 어긋나면 묻는다.
- **즉시 질문**(경계 사이 task): 물을 것만 묻는다. 막아 세우는 전제(`[전제 전n]`)가 맨 앞이다.
- **경계 보고**(등록표 `boundary: report`): 다음 단계가 기다린다. 머리 칸, 세 묶음(물을 것 → 하네스가 고칠 것 → 정한 것), 명령 표, 질문, 답 줄, 펼침, 명령 원문 차례다.
- 1.3.0 전에 시작한 task와 등록표 `boundary: stage`인 task는 옛 화면이다. 묻는 법·답 처리·알림은 「3. 승인 — 옛 화면」(1.2.1 규칙 그대로)을 따른다.

**묻는 방법**
- 대기열은 `board.py --queue`의 순서다(다른 task를 막고 있는 것 → 정해 주실 것이 있는 것 → 요청 순서). 여러 task를 묶어 한 번에 승인받지 않는다. 한 번에 화면 하나다.
- 1.3.0 화면은 출력을 그대로 보이고, 화면의 답 줄대로 받는다(질문마다 `{n}가` / `{n} 확인 먼저` / `{n} 펼쳐`, 전제는 `전{n} 됨`, 경계 보고는 끝에 `진행` / `진행, 단 {조건}` / `결정 {n} 다시` / `멈춤`). 추천을 미리 채우지 않는다. 옛 화면은 `AskUserQuestion`으로 「정해 주실 것」 항목마다 질문 하나(작성자가 쓴 선택지, 추천을 첫 선택지로)와 전체 질문(`승인` / `고칠 것이 있음` / `나눠서 다시` / `보류`)을 낸다. `! 결정 수 상한` 줄이 있으면 `나눠서 다시`를 추천으로 낸다.
- `! 사람의 말` 줄이 작성자 글을 가리키면 묻기 전에 새 작성 에이전트에게 「승인 화면」 절을 한 번 고치게 한다(먼저 `task_set.py {실행 폴더} {id} --screen-snapshot`. 막지는 않는다. 스크립트가 만든 줄이면 그대로 둔다). `! 정한 것·전제의 꼴`, `! 판단 기록`은 고치기 전에 알림으로 지나가지 않는다.
- `task_set.py {실행 폴더} {id} --status 승인대기 n_decide=… …`(`counts:` 값)로 고치고 `screen.py {실행 폴더} {id} --save`로 화면을 남긴 뒤 묻는다(되물을 때도). 화면의 `[기록 점검]` 항목은 사람에게 보인 뒤 **걸린 task의 id로** `task_set.py {실행 폴더} {걸린 id} --record "점검 확인|{코드}|{원문}"`을 남긴다.
- 한 장: `visual.py {실행 폴더} {id}`의 출력을 「보는 자료」로 붙인다. `--save` 전에 `--sheet`를 돌려 그 줄을 보이고 경로를 연다. 올리기도 `--save` 전(`sheet-upload.md`).

**답의 처리** — 답은 `screen.py {실행 폴더} {id} --answer "원문"`으로 풀고, 종료 3이면 되묻는다(답 없는 질문·전제가 남은 `진행`도 되묻는다). 답을 받은 턴에, 다른 일을 하기 전에 `task_set.py {실행 폴더} {id} --record "지점|결정|원문"`으로 「승인 기록」에 원문을 쓴다. 다른 task에 영향을 주거나 애매하면 같은 턴에 `decisions.md`에도 쓴다. **방향을 가른 답**(수단 바꿈, 늘어난 일 붙임·뗌, 범위 넓힘·좁힘)은 `decisions.md` 결정 칸을 `[방향] {무엇을 무엇으로} (버림: {버린 길과 까닭 몇 낱말})`로 쓴다(경계 보고 「지금까지 방향」이 읽는다). **명령을 돌리게 하는 답**(명령을 여는 단계의 승인 답 — 그 kind 모듈 — 과 `cmd` 울타리가 있는 task의 승인)은 지점 칸이나 결정 칸을 `승인`으로 적는다(예 `승인|실행 승인|…`, `승인|위험 수용|…`). `exec.py`는 이 꼴의 답이 있어야 그 지점을 얼린다(보류·거절·되돌림 답은 세지 않는다). 사용자가 직접 실행하기로 한 답은 `승인`으로 적지 않는다. `--record`가 "같은 원문 재사용"으로 거부되면(종료 3) 새 답이면 원문을 그대로 다시 적고, 앞 답을 다시 쓰는 것이 맞으면 `--reuse-answer "{이유}"`를 붙인다.
| 답 | 처리 |
|---|---|
| 승인, `진행`, 또는 산출물을 바꾸지 않는 답 | `완료`, `approved`. 자식을 만든다. 등록표 `stages`가 있는 task는 `stage: 끝` 전에는 `완료`로 바꾸지 않는다(묻는 단계는 `승인대기`, 메인이 실행하는 단계는 `진행`) |
| 준비된 선택지를 고름(작성자나 판정자가 선택지별 문장을 써 둔 것) | 코드 task에는 쓰지 않는다(늘 고치는 task, 아래 행). 그 밖은 그 문장을 산출물에 넣는다(정본이면 그 줄을 그 문장으로 바꾸는 Edit 한 번. 해석하지 않는다. `main-run.md`에 한 줄. 시작 전인 다른 task의 판정 기준이면 `--amend-criteria … --source "사용자 답 {id} {시각}"`). `앞 정본 줄`은 줄마다 `지금:`과 같은지 보고 `바뀜:`으로 Edit 한 번, `decisions.md`에 한 줄. `지금:`이 다르면 산출물을 바꾸는 답이다. `완료` |
| 산출물을 바꾸는 답(깔아 둔 안과 다른 선택, 수정 요청, 추가 요구, `나눠서 다시`, `결정 {n} 다시`, 산출물을 바꾸는 `진행, 단 {조건}`) | 이 task는 `--record "고침|{결정}|{원문}"`(`승인` 지점 아님)으로 적어 `완료`로 닫고 `awaiting_answer_apply: true`. 고치는 task를 `task_set.py … new --from-answer {이 task id}`로 만든다(코드면 코드를 고치는 task, 5절. 커밋한 코드 task는 `나눠서 다시`도 그 커밋 위에서 고친다). 원래 task의 자식은 그 고치는 task에 의존하게 만든다(`spawn_children.py … --depends-on {고치는 task id}`). 산출물을 바꾸지 않는 조건(순서, 때)은 `decisions.md`에 적고 승인 행으로 |
| `{n} 확인 먼저` | `승인대기` 그대로. 그 질문이 기대는 확인 안 한 사실을 읽어서 닫거나(작성자) 탐침 task로 확인한 뒤 같은 화면을 다시 낸다 |
| `{n} 펼쳐` | 기록하지 않는다. 그 질문의 근거(결과 파일의 해당 절)를 읽어 보이고 같은 질문을 다시 낸다 |
| 전제 답(`전제: 전{n} 됨` 등) | `--record "전제|전{n} {값}|{원문}"`. `됨`·`예`면 기다리던 뒤 task가 시작한다. `지금 해 보겠음`이면 그대로 기다린다(다른 흐름은 계속). `안 됨`·`아니오`(막아 세움)면 방향을 다시 정하는 질문을 내고, 정해지면 `--record "전제|전{n} 철회|{원문}"` |
| 「하실 일」을 넘김 | 위임과 답의 표지대로, 탐침 task(5절 표). 명령 단계의 줄이면 표시를 지운 고친 판 |
| 되물음(결정이 아닌 질문) | `승인대기` 그대로. 결과 파일의 해당 절을 읽어 답한 뒤 같은 질문을 다시 낸다. 승인 기록에 `되물음(이해)`나 `되물음(이의)` |
| 보류, `멈춤` | `보류`. 자식을 만들지 않는다. 이 task에 의존하는 task(`board.py --queue`)를 함께 보인다. 커밋 전의 코드 task면 변경을 패치로 치울지(`--park`) 그대로 둘지 함께 묻는다. 커밋한 코드 task는 implementation/main-order.md 「보류」. 다시 열면 `대기` |
| 보류·중단을 골랐는데 함께 적은 말과 엇갈림 | 실행을 끝내지 않고 뜻을 다시 묻는다 |

**하네스가 고칠 것**(경계 보고의 `!` 줄, 알림의 `하네스가 고칠 것 n`)은 경계를 지난 뒤 메인이 정본을 고치는 task(`--origin "판정자 {id} 짚음"`)로 고치고 결과를 알림 한 줄로 낸다. 사람에게 묻지 않는다.

옛 코드 확인 카드는 그 kind 순서 파일의 「코드 확인」 절이다(1.3.0부터 곳마다 답하지 않는다). 위임과 답의 표지는 진입 표.
