## 3. 승인과 알림

`screen.py {실행 폴더} {task id}`의 출력이 승인 화면의 재료다. 메인은 결과 본문을 읽지 않는다. 다만 승인에 올리는 task마다 승인 화면의 항목 하나를 골라 결과 본문의 해당 절과 맞는지 **표본 대조**한다. 어긋나면 새 작성 에이전트에게 「승인 화면」 절을 고치게 한다.

**알림으로 지나가는 것**(한 줄로 알리고 답을 기다리지 않는다. `approval_mode: 알림`, 상태 `완료`). 어느 task가 어떤 조건에서 지나가는지는 그 kind의 `references/kinds/{정의}/main-order.md`에 있다. 조건이 하나라도 어긋나면 승인으로 간다.
사용자의 답을 옮긴 task(`origin: 사용자 …`)의 알림은 `screen.py`가 가른다. 등록표 `notify`가 `never`인 task는 알림으로 지나가지 않는다.

**승인을 묻는 방법**
- 대기열은 `board.py --queue`의 순서다(다른 task를 막고 있는 것 → 정해 주실 것이 있는 것 → 요청 순서). 사용자가 목록을 달라고 하면 보여 주고 순서를 바꾼다. 여러 task를 묶어 한 번에 승인받지 않는다.
- 본문에 화면의 재료를 그대로 보여 준 뒤 `AskUserQuestion`으로 묻는다(`묻기:` 줄이 나오면 일반 메시지). 「정해 주실 것」은 항목마다 질문 하나로 내고(선택지는 작성자가 쓴 것, 추천을 첫 선택지로), 마지막에 이 task 전체에 대한 질문을 낸다: `승인` / `고칠 것이 있음`(기타에 적음) / `나눠서 다시` / `보류`. 한도를 넘으면 이어서 묻는다. 「정해 주실 것」이 없으면 전체 질문 하나만 낸다. `screen.py`에 `! 결정 수 상한` 줄이 있으면 `나눠서 다시`를 첫 선택지(추천)로 낸다.
- 메시지 하나로 판단하게 쓴다. 번호로만 부르지 않는다. 단정은 확인한 범위까지. 확정할 것을 문장으로 적는다.
- `task_set.py {실행 폴더} {id} --status 승인대기 n_decide=… …`(`screen.py`의 `counts:` 값)로 고치고 `screen.py {실행 폴더} {id} --save`로 화면을 남긴 뒤 묻는다(되물을 때도). 화면의 `[기록 점검]` 항목은 사람에게 보인 뒤(알림 줄로 보인 것도) **걸린 task의 id로** `task_set.py {실행 폴더} {걸린 id} --record "점검 확인|{코드}|{원문}"`을 남긴다(그 걸림은 다시 찍히지 않는다. 판정 뒤 바뀜(R3)은 확인 뒤 다시 바뀌면 다시 걸린다).

**승인 요청 꼴** — 승인을 묻는 task는 질문 앞 본문에 아래 여섯 칸을 이 차례로 먼저 쓴다. 화면 머리 세 줄이 있으면 1, 2, 6을 대신한다. 항목의 `[n]`은 그대로 옮긴다.
등록표 `notify`가 `by_decide`이고 코드 폴더에 쓰는(`writes_code_dir`) task가 `screen.py` "알림 조건: 충족"이고 자체 검증을 전부 통과하면 묻지 않고 알림으로 완료한다. 알림 줄에는 알릴 것·확인 안 된 것 건수와, 메인이 뒤 task로 넘긴 것을 한두 줄로 적는다.
1. 무엇에 대한 승인인지 한 줄(예: "그 task가 만든 코드를 코드 폴더에 커밋해도 되는지").
2. 그 task가 무엇이고 왜 필요한지(실행 목표 안에서의 자리, 앞뒤 task와의 관계).
3. 만든 것(파일·도구마다 한 줄로 하는 일).
4. 검사 결과(판정 통과 수, 재시도가 있었으면 무엇이 걸렸고 어떻게 고쳤는지, 테스트·변이).
5. 승인 전에 알아 둘 것(승인 화면 「하실 일·허용 요청」·「알릴 것」·「확인 안 된 것」의 요지): 항목마다 "하실 일 있음/없음"을 먼저 적는다. 하실 일이 없으면 누가(메인·어느 task) 처리하는지만 짧게 적고, 하실 일이 있는 것만 풀어 쓴다. 결정하실 것이 승인 하나뿐이면 그렇게 밝힌다.
6. 승인하면 다음에 무엇을 하는지.

여섯 칸 뒤에 `visual.py {실행 폴더} {id}`의 출력을 「보는 자료」로 붙인다. `--save` 전에 `--sheet`를 돌려 그 줄을 보이고 경로를 연다. 올리기도 `--save` 전(`sheet-upload.md`).

**답의 처리** — 번호나 짧은 꼴의 답(`3 가`, `이의 4`, `나머지 남김`)은 `screen.py {실행 폴더} {id} --answer "원문"`으로 풀고, 종료 3이면 되묻는다. 답을 받은 턴에, 다른 일을 하기 전에 `task_set.py {실행 폴더} {id} --record "지점|결정|원문"`으로 「승인 기록」에 원문을 쓴다. 다른 task에 영향을 주거나 애매하면 같은 턴에 `decisions.md`에도 쓴다. **명령을 돌리게 하는 답**(명령을 여는 단계의 승인 답 — 어느 단계인지는 그 kind 모듈에 있다 — 과 `cmd` 울타리가 있는 task의 승인)은 지점 칸이나 결정 칸을 `승인`으로 적는다(예 `승인|실행 승인|…`, `승인|위험 수용|…`). `exec.py`는 이 꼴의 답이 있어야 그 지점을 얼린다(`devflow_lib.approval_line`. 보류·거절·되돌림 답은 세지 않는다). 사용자가 직접 실행하기로 한 답은 `승인`으로 적지 않는다. `--record`가 "같은 원문 재사용"으로 거부되면(종료 3) 이 승인 요청 뒤에 받은 답인지 본다. 새 답이면 사용자 원문을 그대로 다시 적고, 앞 답을 다시 쓰는 것이 맞으면 `--reuse-answer "{이유}"`를 붙인다(승인 줄 끝에 `| 재사용 답: {이유}` 칸이 붙고, 이 답으로는 명령 지점을 얼리지 않는다).
| 답 | 처리 |
|---|---|
| 승인, 또는 산출물을 바꾸지 않는 답 | `완료`, `approved`. 자식을 만든다. 등록표 `stages`가 있는 task는 `stage: 끝` 전에는 `완료`로 바꾸지 않는다. 사람에게 묻는 단계는 `승인대기`, 메인이 실행하는 단계는 `진행`(`stage=` 값과 함께 바꾼다) |
| 「정해 주실 것」에서 준비된 선택지를 고름(작성자나 판정자가 선택지별 문장을 써 둔 것) | 그 문장을 산출물에 넣는다(정본이면 해당 줄을 그 문장으로 바꾸는 Edit 한 번. 해석하지 않는다. `result.md`에는 반영 표시를 하지 않고 `main-run.md`에 한 줄. 아직 시작 전인 다른 task의 판정 기준이면 `--amend-criteria … --source "사용자 답 {id} {시각}"`). 하위 줄 `앞 정본 줄`은 줄마다 그 파일:줄이 `지금:`과 같은지 보고 `바뀜:`으로 Edit 한 번, `decisions.md`에 한 줄(아직 시작 전인 task의 판정 기준이 그 줄에 기대면 위와 같이 정정). `지금:`이 다르거나 적히지 않은 줄까지 바꿔야 하면 산출물을 바꾸는 답으로 처리한다. `완료`. 산출물을 고치는 task(코드면 코드를 고치는 task)를 따로 만들지 않는다 |
| 산출물을 바꾸는 답(깔아 둔 안과 다른 선택, 수정 요청, 추가 요구, `나눠서 다시`) | 이 task는 `완료`로 닫고 `awaiting_answer_apply: true`. 같은 블록에 고치는 task를 메인이 `task_set.py … new --from-answer {이 task id}`로 만든다(코드를 고치면 코드를 고치는 task, 5절). 원래 task의 자식은 만들되 그 고치는 task에 의존하게 한다(`spawn_children.py … --depends-on {고치는 task id}`). 의존을 일찍 푸는 경우는 5절 |
| 「하실 일」을 넘김 | 위임과 답의 표지대로, 탐침 task(5절 표). 명령 단계의 줄이면 표시를 지운 고친 판 |
| 되물음(결정이 아닌 질문) | 상태는 `승인대기` 그대로. 결과 파일의 해당 절을 읽어 답한 뒤 같은 질문을 다시 낸다. 승인 기록에 `되물음(이해)`나 `되물음(이의)`로 적는다 |
| 보류 | `보류`. 자식을 만들지 않는다. 고를 때 이 task에 의존하는 task(`board.py --queue`)를 함께 보인다. 커밋 전의 코드 task면 커밋 안 된 변경을 패치로 치울지(`task_set.py {id} --park`, 「치워 두기」) 그대로 둘지를 함께 묻는다. 다시 열면(사용자 답) `대기`로 |
| 보류·중단을 골랐는데 함께 적은 말과 엇갈림 | 실행을 끝내지 않고 뜻을 다시 묻는다 |

코드 확인 카드는 그 kind 순서 파일의 「코드 확인」 절이다. 위임과 답의 표지는 진입 표.
