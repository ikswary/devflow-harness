## 8. 메인의 컨텍스트

- 결과 파일과 정본을 전문으로 읽지 않는다. 승인 화면은 `screen.py`, 상태는 `board.py`, 판정은 `judge.md`의 「통과 못 한 기준」과 「확인 방법 요약」만 본다. 전문이 필요한 일은 에이전트에게 맡긴다.
- 에이전트의 결과 본문을 다른 에이전트의 프롬프트에 옮겨 적지 않는다. 경로를 준다.
- 메인 컨텍스트는 `screen.py`와 `board.py --ready` 출력의 맨 끝 `메인 컨텍스트:` 줄로 본다. 승인·알림·task 띄우기마다 돌리는 스크립트라 따로 세지 않는다. `측정 불가`가 이어지면 승인과 알림 15건을 문턱으로 본다. 두 스크립트를 쓰지 않는 승인(배포 결과, 7절의 밖으로 나가는 명령)만 5건 이어지면 `python context-size.py`로 잰다.
  - **200K**를 넘으면 실행 중 에이전트가 0이고 모든 반환이 머리 파일에 반영된 시점(흐름을 통합 브랜치에 넣은 직후가 정해진 정리 지점이다)에 "`/clear` 뒤 `devflow-harness 이어서`"를 권한다. 새 task는 계속 띄운다.
  - **300K**를 넘으면 새 task를 띄우지 않고(1절 4의 "질문 직전에 띄우기"보다 이것이 앞선다) 정리 지점을 기다려 같은 것을 권한다.
  - 200K에서 바로 막지 않는 것은 사람이 없을 때 실행이 멈추지 않게 하기 위해서다. 메인은 턴마다 컨텍스트 전체를 다시 보내므로(2026-10-29 실행: 99턴에 15.4M, 재개 직후 바닥 약 120K) 문턱이 낮을수록 반환 하나를 처리하는 값이 싸다. 문턱 값은 `scripts/devflow_lib.py`의 `CTX_ADVISE`·`CTX_STOP`이다.
- 단계 파일은 처음 필요할 때 한 번 읽고 다시 읽지 않는다(`/clear`·요약 뒤, 하네스 판본이 바뀐 뒤에는 다시 읽는다). 서로 독립인 확인(스크립트, `grep`, 상태 조회)은 한 `Bash`에 묶는다.
