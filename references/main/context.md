## 8. 메인의 컨텍스트

- 결과 파일과 정본을 전문으로 읽지 않는다. 승인 화면은 `screen.py`, 상태는 `board.py`, 판정은 `judge.md`의 「통과 못 한 기준」과 「확인 방법 요약」만 본다. 전문이 필요한 일은 에이전트에게 맡긴다.
- 에이전트의 결과 본문을 다른 에이전트의 프롬프트에 옮겨 적지 않는다. 경로를 준다.
- 메인 컨텍스트는 `screen.py`와 `board.py --ready` 출력의 맨 끝 `메인 컨텍스트:` 줄로 본다. 승인·알림·task 띄우기마다 돌리는 스크립트라 따로 세지 않는다. `측정 불가`가 이어지면 승인과 알림 15건을 문턱으로 본다. 두 스크립트를 쓰지 않는 승인(배포 결과, 7절의 밖으로 나가는 명령)만 5건 이어지면 `python context-size.py`로 잰다.
  - **권함 문턱**(「이번 실행의 값」 `메인 컨텍스트 권함`, 시작값 300K)을 넘으면 실행 중 에이전트가 0이고 모든 반환이 머리 파일에 반영된 시점(흐름을 통합 브랜치에 넣은 직후, 판정이 몰린 뒤 에이전트가 모두 반환한 직후가 정해진 정리 지점이다)에 "`/clear` 뒤 `devflow-harness 이어서`"를 권한다. 새 task는 계속 띄운다.
  - **멈춤 문턱**(`메인 컨텍스트 멈춤`, 시작값 500K)을 넘으면 새 task를 띄우지 않고(1절 4의 "질문 직전에 띄우기"보다 이것이 앞선다) 정리 지점을 기다려 같은 것을 권한다.
  - 권함 문턱에서 바로 막지 않는 것은 사람이 없을 때 실행이 멈추지 않게 하기 위해서다. 메인은 턴마다 컨텍스트 전체를 다시 보내므로(2026-10-29 실행: 99턴에 15.4M) 문턱이 낮을수록 반환 하나를 처리하는 값이 싸지만, 재개 한 번도 약 2.5M(재개 직후 바닥을 캐시에 다시 씀. 1.0.4 실행의 바닥은 120~130K)이라 재개 사이 메인 호출이 적으면 낮은 문턱이 손해다. 「이번 실행의 값」에 행이 없으면 시작값(등록표 `run-keys.md`)으로 읽는다.
- 재개 바닥은 실행마다 잰다: 재개가 끝날 때 `journal.md`에 `재개 바닥 {n}K` 메모를 남긴다(0절 4). 바닥의 대부분은 하네스 밖(시스템 프롬프트, 도구 정의, MCP 서버)이고 재개가 읽는 하네스 문서는 15~20K 토큰쯤이다. 바닥이 150K 이상이면 `screen.py`가 다음 승인 화면에 한 번, 이 프로젝트에 필요 없는 MCP 서버를 끄면 줄어든다는 줄을 낸다.
- 단계 파일은 처음 필요할 때 한 번 읽고 다시 읽지 않는다(`/clear`·요약 뒤, 하네스 판본이 바뀐 뒤에는 다시 읽는다). 서로 독립인 확인(스크립트, `grep`, 상태 조회)은 한 `Bash`에 묶는다. 하네스 스크립트가 아닌 진단 출력(긴 목록, 로그)은 파일로 쓰고 필요한 줄만 본다.
