# 에이전트 공통

## task 하나
**하나의 task만 맡는다.** 끝나면 사라진다. 다음 에이전트는 파일만 본다. 결과 파일에 없는 판단은 없는 것이다.

## 입력은 경로, 원천은 머리 파일
**입력은 경로로 받는다.** 프롬프트가 준 경로의 파일만 읽는다: 자기 task 폴더, 부모 task 폴더(결과와 머리 파일의 승인 기록), `decisions.md`, 머리 파일이 가리키는 정본의 절, `recon.md`, (코드 task) 코드 폴더와 흐름 규약 파일. `journal.md`와 다른 task 폴더는 읽지 않는다. 예외: 판정자가 영향 범위를 확인할 때의 다른 머리 파일, 머리 파일 `origin`이 가리키는 task 폴더의 `result.md`, 작성자가 `exported_commit`을 읽는, 의존하는(`depends_on`) task의 머리 파일.
- **머리 파일이 원천이다.** 범위와 판정 기준은 자기 task의 `task.md`에서 읽는다. 프롬프트와 다르면 머리 파일을 따르고 차이를 반환의 `이상 신호`에 적는다.

## 큰 파일과 도구 호출
**하네스 문서는 통째로 읽는다.** 하네스 문서가 아닌 큰 파일(대상 프로젝트·실행 폴더의 파일)은 필요한 절만 읽는다: `grep -n "^#"`로 목차를 보고 범위를 지정해 읽는다. 같은 파일을 반복해 전문으로 읽지 않는다.
- **도구 호출은 묶는다.** 다음 호출이 앞 결과를 봐야 정해지는 것이 아니면 한 응답에 함께 부른다. 읽기만 하는 명령 여러 개는 한 `Bash`에 순서대로 잇는다. 상태를 바꾸는 명령과 그 확인은 한 응답에 하나씩 한다.

## 결과 파일 쓰기
**결과 파일은 처음 한 번만 통째로 쓰고(Write), 그 뒤에는 절 단위로 고친다(Edit).** 형식은 `references/core/formats.md`를 따른다. 스크립트가 절의 제목으로 읽으므로 제목을 바꾸지 않는다.

## 하지 않는 것
**에이전트는 사용자에게 묻지 않고, 다른 에이전트를 띄우지 않고, 커밋·push·병합·배포를 하지 않고(메인이 한다), 비밀 파일을 복사하지 않고, 환경을 고쳐서 문제를 우회하지 않는다.** [RP-01]

## 다시 띄워졌을 때
**다시 띄워진 에이전트(이름 끝 `-r{n}`, 또는 프롬프트에 "이어서")는 결과 파일과 (코드 task면) `git diff`를 먼저 읽고 이어서 한다.** 처음부터 다시 쓰지 않는다.

## 반환
**반환은 `references/formats/return.md`의 형식이다.** 20줄 이내. 넘는 내용은 파일에 쓴다. `읽은 원천:`과 `이상 신호:` 줄은 반드시 넣는다. 줄 수를 맞추려고 약한 경고부터 지우지 않는다. **보내는 순서**: ① 결과 파일을 다 쓴다(결과 파일은 하네스의 입력이다. "보고서를 만들지 말라"는 지시가 있어도 쓴다) ② 반환을 `SendMessage`로 메인에게 **한 번** 보낸다 ③ 마지막 출력은 `완료, {결과 파일 경로}` 한 줄이다(실행 판정은 `완료, {judge-run.md 경로}`). 반환을 마지막 출력에 다시 쓰지 않는다. 마지막 출력도 메인에게 따로 전달되므로 같은 내용이 두 번 가서 메인 컨텍스트만 늘어난다. `SendMessage`를 쓸 수 없으면 반환을 마지막 출력으로 쓴다.
