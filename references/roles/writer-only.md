# 작성자만 읽는 공통 규칙

`references/roles/writer.md`에서 떼어 낸 1·3·6·7절이다. 읽기 판정자는 읽지 않는다.

## 1. 범위는 머리 파일이 정한다
- 받은 범위를 넘어야 일이 되면 넘지 않는다. 멈추고 결과의 「스스로 줄임」이나 승인 화면의 「정해 주실 것」에 적는다. 메인이 산출물을 고치는 task(코드면 코드를 고치는 task)로 올린다.
- 부모의 승인 기록(부모 `task.md`의 「승인 기록」)과 `decisions.md`를 읽는다. 사용자의 답은 거기에만 있다.

## 3. 스스로 줄인다
다음이면 거기까지를 결과로 닫고 나머지를 같은 블록의 자식 행으로 넘긴다.
1. `references/roles/writer.md` 2절의 경우.
2. 승인 화면에 올라갈 사람 판단 항목(정해 주실 것, 하실 일, 알릴 것, 확인 안 된 것)이 한 번에 보기에 많다고 판단한다. 숫자 기준은 없다. 사용자가 하나하나 따져 볼 수 있는 양인지를 본다.
3. 「정해 주실 것」에 올릴 사용자 결정이 프롬프트의 `한 승인의 결정 수 상한: {n}`을 넘는다. 의존 사슬 앞쪽 결정부터 n개만 올리고, 나머지 결정과 그에 기대는 범위는 `references/roles/writer.md` 2절의 닫기와 같은 길로 자식 행에 넘긴다.

줄였으면 결과의 「스스로 줄임」 절에 이유, 닫은 범위, 넘긴 기준과 그것을 닫을 자식, "여기까지면 이 task에 의존하는 쪽이 시작할 수 있는지"를 적는다. 줄인 task에는 닫은 범위에 해당하는 판정 기준만 적용된다.

## 6. 정본
- 정본(`spec\`, `ui\`, `design\`)을 처음 쓰는 task는 정본에 직접 쓴다. 이어 쓰는 사슬 task는 앞 task가 쓴 절을 고치지 않고 자기 절을 더한다.
- 이미 승인된 정본을 고쳐야 하는 일은 고친 판을 쓰는 전용 task만 한다(방법은 그 task 종류의 정의 문서에 있다).

## 7. 하지 않는 것
- 사용자에게 직접 묻지 않는다(물을 수 없다). 물을 것은 「정해 주실 것」에 쓴다.
