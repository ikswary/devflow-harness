# 확인하지 못한 것과 다음에 확인할 것

시험 효율화·규칙과 검사를 묶는 시험·목적 시험 이관 실행(2026-11-17, 흐름 `harness-tests`)에서 확인하지 못했거나 일부러 미룬 것이다. 이번 실행은 배포하지 않았다.

- 판을 낼 때 확인: 목적 시험 자료의 T004 코드 사본 폴더가 비어 있다. 준비 스크립트는 `! 코드 사본이 비었음`을 내고 빈 커밋으로 끝까지 돌지만 작성자가 코드를 읽을 수 없어 목적 시험이 성립하지 않으므로, 목적 시험 전에 자료를 다시 채운다.
- 판을 낼 때 확인: 옮긴 준비 스크립트로 목적 시험 전체(작성자·판정·화면·승인자)를 돌려 보지 않았다. 실제 자료로 T051과 T004를 준비하고 `board.py`가 종료 0인 것까지만 봤다.
- 판을 낼 때 확인: 비공개 금지 낱말 검사는 환경 변수 `DEVFLOW_FORBIDDEN`이 없어 건너뛰었다(전체 시험의 skipped 2에 든다). 비공개 목록으로 새 파일을 대조하지 않았다.
- 실제 세션에서 확인: 도구 호출 훅이 도구를 다 돌린 뒤 실패하는 경우와 패널 닫기 훅의 실패는 시험 엔진에서 일으키지 못해 시험하지 않았다(패널 닫기는 `claude plugin validate` 출력의 등록 줄로만 확인). 실패 처리의 유예 시간(1초) 안에 상태 기록이 끝나는지도 시험 엔진으로만 봤다.
- 실제 세션에서 확인: `_workspace`가 없는 폴더에서 도구 호출 훅을 실패시켜 패널의 실패 줄이 사라지는지 보지 않았다. 틀리면 패널에 실패 줄이 남는 옛 증상이 그대로다.
- 실제 세션에서 확인: 사람이 도구 실행을 중단하면 훅 실패로 잡혀 패널에 `판정 실패: 훅 tool.call 실패: …`가 잠깐 뜰 수 있는지 확인하지 못했다.
- 실제 git 훅 확인: 실제 pre-commit 훅 안에서 전체 시험을 돌려 보지 않았다. 훅이 `git rev-parse --local-env-vars` 목록과 `GIT_NAMESPACE`·`GIT_REFERENCE_BACKEND` 밖의 변수로 저장소를 지정하면 목적 시험 준비의 git 환경 분리가 막지 못한다.
- 다음 변경 때 확인: 정적으로 읽지 못하는 닿음(문자열을 이어 만든 경로, 동적 import)이 있는 시험은 `tests/py/select_tests.py`가 고르지 못할 수 있다. 커밋 전 전체 병렬 시험이 빠진 것을 잡는다.
- 다음 변경 때 확인: 병렬에서 드물게 깨지는 시험이 없다고 가정했다(설계 때 두 번, 병렬 시험 task에서 두 번 돌려 깨짐 없음). 깨지면 그 시험의 원인을 고친다.
