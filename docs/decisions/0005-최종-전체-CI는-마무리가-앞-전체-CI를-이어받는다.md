# 최종 전체 CI는 마무리가 앞 전체 CI를 이어받는다

- 날짜: 2026-11-18
- 정한 사람: 사용자(원문 "2.나"(T002), 이어받음 관문의 문장 "1가"(T028), 위험 수용 "승인(위험 수용)"(T033, 2026-11-19))
- 상태: 유효(1.3.1 규칙이다. 이 실행의 마무리는 설치본 1.3.0 규칙이라 전체를 새로 돌았다)

## 결정
- 마무리의 최종 배포 후보 CI는 코드가 같을 때만 앞의 전체 검증을 이어받는다. 이어받을 원천은 흐름이 둘 이상이면 가장 늦게 완료된 합치기의 「최종 배포 후보 CI」(범위 전체 검증, 통과 못 한 기준 없음), 흐름이 하나면 그 흐름에서 가장 늦게 완료된 코드 task의 판정 파일 「전체 검증 기록」이다.
- 같은 코드 판별: 합치기 원천은 검증 commit이 문서 커밋 전 끝과 같아야 하고, 코드 task 원천은 기록한 검증 tree가 그 끝의 tree와 같아야 한다. 그 뒤 바뀐 파일은 이 마무리의 문서 커밋 파일뿐이어야 한다. 하나라도 아니면 지금처럼 전체를 새로 돈다.
- 이어받아도 새로 돌리는 것은 `recon.md` 「문서를 읽는 검사」, 생성 대조, 결과물을 시험하는 프로젝트의 빌드다. 기록은 `- 범위: 이어받은 전체 검증`, `- 이어받은 CI: {task id} {sha}`, `- 그 뒤 바뀐 파일:` 줄이다.
- 완료 관문(`final_candidate_ci_problem`)은 원천을 같은 함수(`--inherit-ci`)로 다시 대조하고, 판정자가 적은 `- 그 뒤 바뀐 파일:` 목록 밖의 변경만 다시 본다.
- 이 관문이 판정자가 적은 목록을 믿는 위험은 사용자가 받아들였다. 판정자가 코드 파일을 그 줄에 적으면 막지 못한다(문서 커밋 전 끝이 실행 승인 때 머리 키에서 지워져 관문이 따로 읽을 곳이 없다).

## 버린 길
- (가) 마지막 합치기 CI와 마무리 최종 CI를 그대로 두는 길.
- (다) 마무리 최종 CI 뒤 수정 task마다 닿는 시험만 돌리는 길.
- (라) 마지막 합치기를 영향 검사로 낮추는 길.
- 관문이 git으로 목록을 직접 구하고 T029 범위를 넓히는 길(T028 "1가"가 문장을 낮추는 쪽을 골랐다).

## 근거
같은 코드를 마지막 합치기 CI와 마무리 최종 CI가 두 번 검사했고, 최종 CI 뒤 수정 task마다 실행 판정이 전체 시험을 다시 돌렸다. 이 저장소의 전체 시험은 병렬로 약 5~7분이다.
