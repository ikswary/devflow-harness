# 흐름별 검증과 재검증에서 코드를 고치기로 한 범위

- 날짜: 2026-11-18
- 정한 사람: 사용자(원문 "1 아니오, 2 예, 3가, 4나, 5가, 6가 …"(T012), "추천대로"(T021))
- 상태: 유효

## 결정
- `_workspace`가 없는 쉼 상태에서도 다음 판정 회차가 `훅 tool.call 실패: …` 줄만 지운다(`hooks/common.ts`). 이 흐름의 코드로 고쳤다.
- `docs/plugin-practices.md`의 "이름 줍기는 남음" 줄은 이 흐름에서 문서를 고쳤다.
- 사람이 도구 실행을 중단할 때 패널에 실패 줄이 잠깐 남을 수 있는 것은 그대로 둔다.
- 글자 예산 문서의 전제 300자는 문서에만 적고 코드로 재지 않는다. 화면은 전제를 질문 예산으로 잰다고 덧붙였다.
- 목적 시험 준비 스크립트가 git 하위 프로세스에 넘기지 않는 변수는 `git rev-parse --local-env-vars`의 15개에 `GIT_NAMESPACE`·`GIT_REFERENCE_BACKEND`를 더한 것으로 넓혔다.

## 버린 길
- 변수 목록은 백로그로 미루거나 그대로 두는 길(T021).
- 전제 300자는 문서만 고치는 길을 골랐다(T012 6가).

## 근거
도구 중단 때의 실패 줄은 실제 세션에서 확인하지 못했다(`docs/operations/unverified.md`). 변수 목록은 git이 저장소를 바꿀 때 지우는 `--local-env-vars` 목록에 맞췄다.

## 되돌리려면
각 항목의 코드와 시험을 `CHANGELOG.md`의 `1.3.0(이어서)` 행이 가리키는 파일에서 되돌린다.
