# 진행 대시보드 사용 설명서

devflow-harness 실행의 진행 상황을 Claude Code 화면 안에서 보는 기능이다. 독자는 하네스를 쓰는 사람이다.
이 문서는 진행 대시보드만 다룬다. 하네스 전체 사용법은 `SKILL.md`에 있다.

## 1. 무엇인가

화면 안에 보는 자리가 둘 있다. 둘 다 같은 판정(`scripts\board_dash.py`가 낸 JSON)을 읽는다.

| 자리 | 어디 | 평소 모습 |
|---|---|---|
| 띠 | 입력창 바로 위 | 둥근 테두리 상자 안에 요약 한 줄과 버튼 줄(위 테두리에 실행 이름). 지도를 펼치면 흐름별 상태와 의존 지도도 상자 안 |
| 패널 | 입력창 위에 따로 뜨는 창 | 흐름별 상태, 의존 지도, task 줄마다 시작 가능·못 띄움·경과 |

- 보는 실행은 지금 세션의 실행 하나뿐이다. 다른 실행의 요약은 없다.
- 끝난 task(완료·보류·백로그)는 흐름마다 개수로 접힌다. 남은 task는 대기·진행·자체검증·승인대기다.
- 읽기만 한다. 실행 폴더에 아무것도 쓰지 않는다.
- 사용자 설정 statusLine은 건드리지 않는다.
- 보는 곳은 터미널(CLI)이다. 선은 글자와 상자 문자로 그린다.

## 2. 켜지는 조건

1. 하네스 폴더(`{플러그인 폴더}`) 자체가 플러그인이다(`.claude-plugin/plugin.json`). 플러그인이 켜져 있으면 Claude Code가 세션을 시작할 때 훅과 함께 불러온다. 설정에 줄을 더할 일은 없다.
   - 플러그인은 세션 시작 때 불린다. 이 파일들이 들어오기 전에 연 세션에는 없다. 새 세션을 연다.
2. 띠는 이 세션에 보여 줄 실행이 있거나 devflow-harness를 부른 세션에서만 그려진다.
   - 이 세션이 진행하는 실행이 없고 devflow-harness도 부르지 않았으면 아무것도 그리지 않는다.
   - 실행이 있으면 devflow-harness를 부르지 않았어도 그린다.
   - 실행이 없는데 devflow-harness를 불렀으면 그 사실을 적은 한 줄만 테두리 안에 그린다(3.5).
3. 어느 실행을 보일지는 `run.md`의 `session_id`로 고른다(`SKILL.md` 0절 7).
   - 메인이 실행을 시작·재개·다시 열 때 지금 세션의 id를 `run.md` 머리에 적는다. 값은 Bash `echo "$CLAUDE_CODE_SESSION_ID"`의 출력이다.
   - 판정은 `kind: devflow-harness`이고 `session_id`가 지금 세션 id와 같은 실행을 고른다. 여럿이면 `status: 진행`인 것 가운데 `run.md`를 가장 나중에 고친 것이다.
   - `/clear`를 하면 새 세션이라 띠가 사라진다. `devflow-harness 이어서`로 재개하면 새 id로 덮어쓰고 다시 나온다.
   - id를 얻지 못해 `session_id`가 비면 메인이 "대시보드(띠·패널)가 이 실행을 보이지 못합니다"라고 알린다.
4. 판정은 `python` 명령으로 `scripts\board_dash.py`를 돌려 얻는다. `python`이 PATH에 있어야 한다.

## 3. 띠

### 3.1 요약 줄

띠 전체가 `╭─ {실행 폴더 이름} ─╮` … `╰─╯` 둥근 테두리 안에 있다. 위 테두리의 이름은 띠가 좁으면 앞의 날짜(`YYYY-MM-DD-`)를 먼저 떼고, 그래도 넘치면 끝이 `…`가 되며, 그것도 안 들어가면 선만 남는다. 위 테두리 오른쪽 끝 세 칸은 엔진의 접기 표시 `[-]`가 차지해 `╮` 대신 `[-]`로 보이고, 누르면 띠를 접는다.

테두리 안 첫 줄이다. 항목은 이 순서다.

| 항목 | 뜻 |
|---|---|
| 승인 대기 N(가장 오래 …) | 승인대기 task 수. 괄호는 가장 오래 기다린 것의 경과 |
| 할 일 대기 N | `waiting_user`가 찬 남은 task 수(사용자가 할 일이 있음) |
| 에이전트 N | `running_agent`가 찬 남은 task 수 |
| 시작 가능 N | `board.py --ready`가 시작해도 된다고 본 task 수 |
| 상태별 수 | `대기 3, 진행 1, 승인대기 2, 접힘 4`처럼. 0인 상태는 적지 않는다. 접힘은 완료·보류·백로그의 합 |

- 폭이 모자라면 항목을 통째로 뺀다. 순서는 상태별 수, 시작 가능, 에이전트, 가장 오래 기다린 경과다. 승인 대기와 할 일 대기는 끝까지 남고, 그래도 넘으면 줄 끝이 `…`가 된다.
- 경과는 `N분`(60분 미만), `N시간 M분`(24시간 미만), `N일 M시간`이다. 승인대기 task 가운데 `approval_requested`가 있는 것이 하나도 없으면 `?`다.
- 읽지 못한 task가 있으면 상태별 수 끝에 `읽지 못함 N`이 붙는다.

### 3.2 버튼 줄

버튼은 `{단축키}: {이름}` 꼴로 보인다.

| 버튼 | 단축키 | 하는 일 |
|---|---|---|
| 지도 펼치기 / 지도 접기 | m | 흐름별 상태와 의존 지도를 폈다 접는다 |
| 전체 | a | 지도를 실행 전체 한 장으로 |
| 흐름 이름 | b, c, d, f, g… | 그 흐름의 지도만 |
| 패널 열기 | p | 패널을 연다 |

- 고른 지도 단위 앞에 `*`가 붙는다. 처음에는 `*전체`다.
- 흐름 버튼의 단축키는 흐름 차례대로 `bcdfghijklnoqrstuvwxyz`다(a·e·m·p는 건너뜀). 흐름이 이보다 많으면 나머지는 단축키 없이 클릭으로만 누른다.
- 흐름 버튼은 `flow.md`가 있는 흐름에만 있다. 흐름 없이 `block` 값으로 묶인 줄과 `기타`에는 없다.
- 버튼은 띠에 들어가야 단축키가 된다. 클릭하거나 `ctrl+x tab`으로 들어간다. 나올 때는 `Esc` 한 번이다.
- 지도를 접은 채로 흐름 버튼을 누르면 고른 표시만 바뀌고, 펼치면 그 단위의 지도가 나온다. 패널 열기는 펼침도 지도 단위도 바꾸지 않는다.
- 처음 그릴 때와 `/clear` 뒤에는 접힘·`전체`다. 판정이 바뀌어 다시 그려도 펼침과 고른 단위는 유지된다. 고른 흐름이 사라지면 `전체`로 돌아간다.

### 3.3 펼친 지도 읽는 법

버튼 줄 아래에 이 순서로 나온다. 패널의 흐름별 상태 줄과 의존 지도도 모양이 같다. 패널에만 더 있는 것은 4.2에 있다.

1. 흐름별 상태 줄: 줄 이름, `flow.md`의 상태, `받아오기 대기 N`이 있으면 그것. 흐름 없는 task는 `block` 값(없으면 `기타`) 줄에 든다.
   - 띠에서는 흐름 없는 줄(`block` 값·`기타`) 가운데 이름만 남는 줄을 그리지 않는다. 공통 제목 뒷부분(`설계 · 시험 리뷰 …`)을 실은 줄만 남는다. 패널에는 접힌 task 수가 붙으므로 모든 줄이 나온다.
   - 그 줄 task 제목의 과반(둘 이상)이 같은 말로 끝나면 그 공통 뒷부분을 줄 이름 바로 뒤에 ` · {뒷부분}`으로 한 번 적는다(예: `설계 · 시험 리뷰 상위 10 지적 개선`). 뒷부분 맨 앞의 공백과 구분 기호(`—`·`-`·`:`·`·`)는 뗀다.
2. 의존 지도: task 하나가 한 줄이다. 같은 task는 두 번 나오지 않는다.
   - task 줄은 `{선 글자}{상태 기호} {id} {제목}  {줄 끝}`이다. 제목과 줄 끝 사이는 두 칸이다.
   - 제목은 공통 앞부분(실행 전체 기준, 예: `진행 대시보드 — `)과 그 줄의 공통 뒷부분(1에서 ` · ` 뒤에 적힌 것)을 뺀 것이다. 빼고 남은 끝의 공백과 구분 기호도 뗀다. 폭을 넘으면 끝이 `…`다.
   - 상태 기호는 아래와 같다. 대기는 기호가 공백이라 id 앞에 공백이 둘 보인다.

     | 기호 | 상태 |
     |---|---|
     | `✓` | 완료 |
     | `~` | 자체검증 |
     | `>` | 진행 |
     | `?` | 승인대기 |
     | 공백 | 대기 |
     | `-` | 보류 |
     | `b` | 백로그 |

   - 띠의 줄 끝은 상태 낱말(`대기`·`진행`·`자체검증`·`승인대기` 등)이다. 아래의 `함께 의존`·`다른 흐름에 의존`·`선 생략`이 있으면 ` · `로 이어 붙는다. 패널은 여기에 시작 가능·못 띄움·경과가 더 붙는다(4.2).
   - 왼쪽의 선(`├─`·`└─`·`│`)은 "끝나야 시작할 수 있는 관계" 한 종류다. 부모(`parent`)와 의존(`depends_on`)을 나누지 않는다. 먼저 끝나야 하는 task가 위에 있고, 그것을 기다리는 task는 그 아래에 3칸 더 들여 쓰인다.
   - `├─`·`└─`는 위 task(먼저 끝나야 하는 task)의 상태 기호와 같은 열에 있고, 그 뒤 한 칸 띄고 기다리는 task의 상태 기호가 온다. `├─`는 같은 task를 기다리는 task가 아래에 더 있다는 뜻이고 `└─`는 마지막이라는 뜻이다. 그 사이 줄의 그 열은 `│`다. 한 task를 기다리는 task들은 그 task 바로 아래부터 id 순으로 이어진다.
   - 한 task가 그려진 task 여럿에 의존하면 선은 그 가운데 하나(id 순으로 마지막)에서만 온다. 나머지는 줄 끝에 `함께 의존: T002`(여럿이면 `, `로)로 적는다. `함께 의존`에 적힌 task는 이 줄보다 아래에 있을 수도 있다.
   - 흐름 하나를 고르면 다른 흐름의 task에 의존하는 task의 줄 끝에 `다른 흐름에 의존: T012(흐름)`이 붙는다.
   - 끝난 task(완료·보류·백로그)는 남은 task가 의존할 때만 보이고, 그 줄은 흐리게(선 글자까지) 그려진다. 줄 끝은 상태 낱말(과 `함께 의존`·`선 생략`)뿐이다. 남은 task의 줄에 지나가는 선은 흐리지 않다.
   - 의존이 고리를 이루면 지도 맨 위에 `의존 고리: T001 → T002 → T001`이 나온다.
   - 남은 task가 없으면 `남은 task 없음`이다.

예(폭 80, 띠). 진행 T001을 T002·T003이 기다리고, T004는 T002를, T005는 T002·T003을, T007은 완료된 T006을 기다린다.

```
> T001 공통  진행
├─   T002 패널  대기
│  └─   T004 패널 검증  대기
└─   T003 띠  대기
   └─   T005 전체 검증  대기 · 함께 의존: T002
✓ T006 질문  완료
└─   T007 설계  대기
```

T005의 선은 T003(id 순으로 마지막)에서만 오고 T002는 `함께 의존`으로 적힌다. T006 줄은 흐린 글씨다.

띠에 없는 것: 끝난 task의 흐름별 개수, 못 띄움 이유 글자, 할 일 대기 내용, 외부 작업, task별 경과는 띠에 나오지 않는다. 이것들은 패널에서 본다(4절). 띠에서는 요약 줄의 숫자로만 보인다.

### 3.4 숨기기

`ctrl+x ctrl+a`는 띠 전체를 접어 숨긴다. 엔진의 조작이라 숨기면 엔진의 안내 한 줄만 남는다. 다시 누르면 돌아온다. 지도 펼치기·접기와는 별개다.

### 3.5 실행이 없을 때

devflow-harness를 부른 세션인데 보여 줄 실행이 없으면 그 사실을 적은 한 줄이 테두리 안에 나오고(위 테두리에 이름 없음) 버튼은 없다.

| 줄 | 뜻 |
|---|---|
| `이 세션이 진행하는 실행 없음` | `session_id`가 이 세션 id인 실행이 없다 |
| `세션 id를 알 수 없어 실행을 고르지 못함` | 이 세션의 id를 얻지 못했다 |
| `판정 결과 없음` | 아직 판정이 한 번도 나오지 않았다 |

## 4. 패널

### 4.1 열고 닫기

| 하는 일 | 방법 |
|---|---|
| 열기 | 입력창에서 `/harness-panel`, 또는 띠의 `p: 패널 열기` |
| 이미 열려 있을 때 | 둘째 패널이 생기지 않는다. 닫히지도 않는다(토글 아님) |
| 닫기 | `Esc` 뒤 `ctrl+x x`. 또는 패널의 닫기 표시를 누른다 |

- 패널은 저절로 열리지 않는다. devflow-harness를 불러도, 띠가 그려져도 열리지 않는다.
- 패널을 닫으면 지도 단위와 펼침이 처음 값(`전체`·접힘)으로 돌아간다. 띠의 지도 단위와는 따로다.
- 연 패널은 키보드를 가져가지 않는다. 키는 열기 전에 있던 곳(`/harness-panel`이면 입력창, 띠 버튼이면 띠)에 남는다.

### 4.2 내용

위에서부터 이 순서다.

1. 머리 줄: `{실행 이름} · 지도: {고른 단위}`. 오류가 있으면 아래에 `판정 실패: …`가 붙는다.
2. 버튼 줄
3. `흐름별 상태`: 줄마다 이름, `flow.md` 상태, `받아오기 대기 N`, 어긋남, 접힌 task 개수(`완료 12 · 보류 1`)
4. `의존 지도`: task 줄마다 id·제목·상태와 줄 끝, 할 일·외부 작업은 아래 줄. 모양은 3.3과 같다
5. `정리 안 된 값`: 끝난 task에 `running_agent`·`external_progress`·`waiting_user`가 남아 있으면 id와 키 이름
6. `읽지 못함`: 머리 파일을 읽지 못한 task와 이유

줄 끝 글자와 아래 줄:

| 글 | 자리 | 뜻 |
|---|---|---|
| `시작 가능 {경과}` | 줄 끝 | 의존이 풀렸고 지금 띄워도 된다. 경과는 풀린 뒤 기다린 시간 |
| `못 띄움: {이유}` · `기다림 {경과}` | 줄 끝 | 의존은 풀렸지만 띄우면 안 된다. 이유는 `흐름 상한 {n}`, `폴더 사용 중`, `받아오기 먼저`, `안 합친 흐름: {흐름들}`, `사용자 할 일 대기` |
| `판정 못 함(…)` | 줄 끝 | `읽지 못한 task에 의존` 또는 `flow.md 읽지 못함` |
| `승인 대기 {경과}` | 줄 끝 | 승인대기 task가 기다린 시간 |
| `진행 {경과}` | 줄 끝 | 진행·자체검증 task가 돈 시간 |
| `함께 의존: T002` | 줄 끝 | 선을 긋지 않은 나머지 의존 task(3.3) |
| `다른 흐름에 의존: T012(흐름)` | 줄 끝 | 흐름 하나를 골랐을 때, 다른 흐름의 task에 의존하는 task |
| `선 생략: T012` | 줄 끝 | 아래 4.4 |
| `할 일 대기: …` | 아래 줄 | 사용자가 할 일 한 줄(`waiting_user`). 대기 task는 이게 차 있으면 시작하지 않는다 |
| `외부 작업: …` | 아래 줄 | `external_progress` 값 |

- `시작 가능`과 `못 띄움`은 task 줄의 줄 끝에 붙는다. 줄 끝은 상태 낱말 뒤에 위 표의 차례(시작 가능·못 띄움·판정 못 함·경과, 함께 의존, 다른 흐름에 의존, 선 생략)로 ` · `를 사이에 두고 이어진다. 예: `대기 · 시작 가능 3분`.
- 경과의 앞말이 상태 낱말로 시작하면(띄어쓰기는 보지 않음) 상태 낱말은 빠진다. 예: `진행 35분`, `승인 대기 1시간 2분`. `자체검증 · 진행 5분`은 그대로다.
- `할 일 대기`와 `외부 작업`은 task 줄 바로 아래 줄(덧줄)에 적힌다. 글은 그 task 줄의 id보다 두 칸 오른쪽에서 시작한다. 남은 task에만 있고, 끝난 task에는 이 아래 줄이 없다. 시작 가능·못 띄움·판정 못 함·경과도 남은 task에만 붙는다.
- 줄이 폭을 넘으면 먼저 제목 끝이 `…`로 준다(`…` 하나까지). 그래도 넘으면 들어가지 않는 줄 끝 글을 아래 줄로 내린다. 상태 기호, id, 줄 끝 글은 줄이지 않는다.

예(폭 80, 패널).

```
  T001 설계: 띠  대기 · 시작 가능 3분
? T002 설계: 패널  승인 대기 1시간 2분
> T003 공통 C2  진행 35분
└─   T004 배포  대기 · 못 띄움: 사용자 할 일 대기 · 기다림 10분
       할 일 대기: 비밀 파일 .dev.vars 준비
```

경과의 시각이 없거나 꼴이 틀리면 `?`다.

흐름별 상태 줄의 `어긋남: …`은 `flow.md`와 task 상태가 맞지 않는다는 표시다. 합치기가 완료됐는데 `flow.md`가 `합쳐짐`·`폴더 지움`이 아니거나(`어긋남: 합치기 T031 완료`), 폴더가 없다는 흐름에서 코드를 쓰는 task가 도는 경우(`어긋남: T044 진행`)다.

### 4.3 버튼과 키보드

| 버튼 | 단축키 | 하는 일 |
|---|---|---|
| 전체 | 0 | 지도를 실행 전체로 |
| 흐름·블록 이름 | 1~9, 그다음 a b c d f g… | 그 줄의 지도만. `e`는 건너뛴다 |
| 펼치기 / 접기 | e | 모든 줄의 접힌 task를 줄마다 한 줄(id, 상태, 제목)로 폈다 접는다. 지도는 바뀌지 않는다 |

- 흐름 줄이 34개(숫자 9 + 글자 25)를 넘으면 나머지는 단축키 없이 클릭이나 Tab+Enter로 누른다.
- 단축키는 패널이 키를 가졌을 때만 눌린다.
- 패널에 키를 주는 길은 둘이다.
  1. 띠를 `ctrl+x ctrl+a`로 숨긴 뒤 `ctrl+x tab`
  2. 전체 화면 모드에서 패널을 클릭
- 띠가 보이는 동안 `ctrl+x tab`은 입력창과 띠 사이만 오간다. 패널로 가지 않는다. 띠의 `p`로 연 뒤에도 같다.

### 4.4 선이 넘칠 때

들여쓰기가 `폭 - 30`칸을 넘게 되는 task는 들여 쓰지 않고 지도 맨 끝에 두며, 그 줄 끝에 `선 생략: {id}`를 달아 둔다. 그 아래 task(그 task를 기다리는 task)는 거기서 다시 들여 쓴다. `{id}`는 그 task가 기다리는 task, 곧 먼저 끝나야 하는 task다. 띠와 패널은 같은 폭이면 같은 task를 뗀다. 들여쓰기는 한 단계에 3칸이라 폭 60이면 11단계, 폭 80이면 17단계부터 뗀다.

## 5. 갱신

| 바뀐 곳 | 화면에 따라오는 시간 |
|---|---|
| 이 세션(메인·하위 에이전트)이 바꾼 것 | 5초 안 |
| 다른 세션·다른 터미널이 바꾼 것 | 60초 안 |

- 이 세션의 도구 실행이 끝날 때, 턴이 끝날 때, devflow-harness를 부를 때, 세션을 시작할 때 판정을 다시 한다. 이벤트가 몰리면 0.5초 모아 한 번 돈다.
- 매 분이 바뀐 직후(1초 뒤)에도 한 번 돈다. 경과 시간이 늘어나는 것과 다른 곳의 변경이 따라오는 것은 이 타이머 덕이다.
- 이전 결과와 같으면 화면을 바꾸지 않는다.
- 판정이 실패하면 직전 결과를 두고 오류 한 줄만 기록한다. 오류는 패널 머리 줄 아래 `판정 실패: …`에서 보인다.

## 6. 플러그인 없이 보기

플러그인이 안 불리는 세션이나 다른 터미널에서 같은 실행을 본다. 읽기만 한다. 아래에서 `scripts\`는 하네스 폴더 안의 `scripts\`다.

| 명령 | 내용 |
|---|---|
| `python scripts\board.py {실행 폴더} --ascii` | 흐름별 한 줄 그림을 한 번 찍는다 |
| `python scripts\board_ascii.py {실행 폴더}` | 위와 같은 그림 |
| `python scripts\board_ascii.py {실행 폴더} --watch {초}` | 그 간격으로 화면을 지우고 다시 그린다. 간격은 2초 미만이면 2초로 본다. `Ctrl+C`로 끝낸다 |
| `python scripts\board_dash.py {작업 폴더} --session {id}` | 띠·패널이 읽는 판정 JSON을 그대로 낸다(문제 해결용) |

`{실행 폴더}`는 `_workspace\{실행 이름}`이고 `{작업 폴더}`는 `_workspace`를 품은 폴더다.

그림 읽는 법:

- 흐름마다 한 줄이고 task는 `{종류}[{상태}]{id}`로 이어진다. 상태는 `[v]`완료 `[>]`진행 `[~]`자체검증 `[?]`승인대기 `[ ]`대기 `[-]`보류 `[b]`백로그. 종류는 `S`설계 `F`수정 `V`검증 `R`재검증 `M`합치기 `C`원인 `X`변경 `W`마무리 `D`/`E`배포 `Q`요구사항이고 구현은 비어 있다. 맨 아래에 범례가 있다.
- 줄 끝 괄호에 흐름 상태, 갈라진 곳(`<- main@ba3560f`), `받아오기 대기 N`이 나온다.
- 아래쪽에 승인 대기, 도는 에이전트, 시작 가능(못 띄움)이 한 줄씩 있다.
- 의존 관계 선은 없다. 선은 띠와 패널에만 있다.

## 7. 문제 해결과 알려진 한계

### 7.1 띠가 안 보일 때

위에서부터 확인한다.

1. 이 파일들이 있는 하네스 폴더가 들어온 뒤 연 새 세션인가. 이전에 연 세션에는 플러그인이 없다.
2. `ctrl+x ctrl+a`로 숨기지 않았나. 한 번 더 누른다.
3. devflow-harness를 불렀나, 또는 이 세션의 id가 적힌 실행이 있나(2절). 둘 다 아니면 띠는 그려지지 않는다.
4. `echo "$CLAUDE_CODE_SESSION_ID"`의 값과 `_workspace\{실행}\run.md`의 `session_id`가 같은가. `/clear`를 했으면 다르다. 이어서 재개하면 맞춰진다.
5. `python scripts\board_dash.py {작업 폴더} --session {id}`가 JSON을 내는가. 안 되면 `python` 경로나 폴더를 의심한다. 패널을 열어 첫 줄 아래 `판정 실패: …`도 본다.
6. 설문이 입력창 위를 차지하고 있으면 띠는 비켜 있다. 설문이 끝나면 돌아온다.
7. 하네스 폴더의 스크립트와 플러그인 판본이 어긋나 판정에 흐름·수가 빠지면 띠는 그리지 않고 비킨다. 둘을 같은 판본으로 맞춘다.

### 7.2 알려진 한계

받아들이고 코드는 그대로 둔 것들이다.

| 한계 | 내용 |
|---|---|
| 띠가 있으면 키보드로 패널에 못 감 | 띠가 보이는 동안 `ctrl+x tab`은 입력창과 띠 사이만 오간다. 패널에 키를 주려면 띠를 `ctrl+x ctrl+a`로 숨긴 뒤 `ctrl+x tab`, 또는 전체 화면에서 클릭 |
| 좁은 전체 화면에서 패널을 연 동안 띠가 안 보임 | 전체 화면 모드에서 110열 미만이고 높이가 60줄보다 작으면(본 값: 40·24줄) 입력창 위에 연 패널이 띠 자리를 차지한다. 패널을 닫으면 띠가 돌아온다. 전체 화면이 아니면 함께 보인다 |
| 전체 화면(대화 옆) 배치 | 전체 화면 120열(120×40)에서 패널이 대화 옆에 붙고 띠도 함께 보이는 것을 확인했다. 110열이라는 경계는 엔진 문서 값이고, 실제로 본 폭은 80·100·120·200열이다 |
| 플러그인 API는 미리 보기 | Claude Code 판본이 바뀌면 띠·패널의 동작이 달라지거나 불리지 않을 수 있다. 설계는 plugin-authoring 2.1.286 기준이다 |

### 7.3 끄는 법

`/plugin`에서 devflow-harness를 끄면 다음에 여는 세션부터 띠와 패널이 없다. 이때 하네스의 스킬과 에이전트도 함께 꺼진다. 끈 뒤에도 6절의 명령은 쓸 수 있다.
